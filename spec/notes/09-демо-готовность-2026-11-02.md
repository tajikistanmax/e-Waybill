фокус именно на демонстрации: что показывать, что платформа умеет сама, без чьей-либо
помощи извне.

## Главный тезис для показа

Платформа работает **полностью автономно**. Это не временное ограничение «пока нет
доступа к интеграциям» — это осознанное решение владельца (зафиксировано 29.10.2026):
- Организации/водители/ТС/сотрудники регистрируются и ведутся вручную, в самой
  платформе — без сверки с «Единой платформой», налоговой, ГАИ.
- Юридическая значимость — печатной формой бланка, не квалифицированной ЭП.
- Уведомления — только in-app, без SMS.
- Расчёт топлива, пробега, выручки, зарплаты — весь в платформе, по собственным
  нормативам (перенесённым из legacy).
- Приём оплаты за путевые листы — внутренний баланс, пополняемый администратором
  (не внешний эквайринг) — добавлено 31.10.2026.

Все внешние интеграции (е-Транспорт, налоговая, ГАИ, платёжный шлюз, SMS, нацУЦ) —
**готовый код-заготовка на будущее**, выключенный по умолчанию. Их отсутствие в демо —
не недоработка, а архитектурное решение.

## Демо-сценарий (предложение, порядок показа)

1. **Диспетчер** — создаёт ПЛ 3-С (легковой), проходит весь жизненный цикл: Т1 →
   мед. осмотр → тех. осмотр → оплата → выдача → GPS-трек → возврат → закрытие.
   Показывает печатный бланк.
2. **Инспектор ГАИ** — сканирует QR путевого листа (публичная проверка подписи, без
   входа в систему) — показывает легальность документа прямо с телефона.
3. **Компания (COMPANY_ADMIN)** — свой кабинет: реестр ТС/водителей/сотрудников,
   филиалы, назначение ролей сотрудникам.
4. **Аналитик Минтранса** — реестр организаций/ТС по стране, региональный скоуп (если
   назначен регион — видит только свой регион), отчёт «Стат-1-авто», региональная
   сводка.
5. **Настройки** — движок правил (политики), конструктор доп.полей, тарифы и баланс
   (новое: платная выдача ПЛ, пост-оплата, не блокирует документ).
6. **Разные типы ПЛ** — показать хотя бы по одному представителю: 1-А (автобус), 2-Б
   (грузовой), 5Б-БМ (международный, с дозволом), спецтехника (моточасы), мотоцикл.

## Известные ограничения (говорить прямо, если спросят)

- Электронная подпись — печатная форма бланка, не квалифицированная ЭП нацУЦ
  (осознанное решение, не баг).
- Легаси-данные (2.28 млн историч. ПЛ) требуют повторной миграции — в демо фигурируют
  только новые/демо-данные, не исторический архив.
- Нагрузочное/пентест-подтверждение — пройдено только на масштабе рабочей машины, не на
  целевой инфраструктуре ЦОД (отдельный вопрос, не блокирует демонстрацию функционала).

## Найденные и исправленные реальные баги (не пробелы тестовых данных)

1. **`Brand.netWeight` — NOT NULL без Java-дефолта.** Колонка БД `net_weight NUMERIC NOT NULL
   DEFAULT 0`, но поле сущности `Brand.java` не имело значения по умолчанию, а контроллер
   выставлял его только если явно пришло в запросе. Любая НОВАЯ марка ТС (через сид-скрипт
   ИЛИ через реальную форму «Справочники → Марки» в интерфейсе) без явного `netWeight`
   падала 409 «Конфликт данных» — это баг, который задевал обычную работу администратора,
   не только тестовые скрипты. Исправлено: `private BigDecimal netWeight =
   BigDecimal.ZERO;`.
2. **Обход проверок допуска второго водителя и при замене водителя** (`WaybillService.java`
   — см. changelog 2026-10-30, найдено автономным аудитом) — закрыто ранее в этой сессии.
3. **Мотоцикл выпадал из посуточного расчёта топлива (B10)** (`WaybillCalcAssembler.java` —
   см. changelog 2026-10-30) — закрыто ранее в этой сессии.

## Аудит «упростить платформу, убрать неиспользуемые поля» (запрос владельца 31.10.2026)

Проведена read-only разведка (фоновый агент, без изменений кода): **честных кандидатов на
удаление — ноль с высокой уверенностью**. Архитектура форм намеренно генерическая
(FORM_FIELDS/FieldDefinition — один цикл рендера на все формы), поэтому объявленное поле
гарантированно используется. Четыре пограничные находки (поля возврата платежа, prevHash
аудита, legacyId справочника маршрутов) — все либо осознанно оставлены с объяснением в
коде, либо финансовый/аудиторский след, удаление которого рискованно перед демо и
юридически небезопасно для госплатформы. **Рекомендация: не удалять поля сейчас** —
риск/выгода не в пользу изменений перед понедельником.
