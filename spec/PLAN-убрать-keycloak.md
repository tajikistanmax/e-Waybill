# План: убрать Keycloak, аутентификация внутри платформы (PostgreSQL)

**Решение владельца 23.09.2026:** Keycloak из платформы убрать. Пользователи и вход — своими
силами, хранение — в PostgreSQL, который у нас уже есть.

## Принцип: контракт токена не меняется

Обе службы уже проверяют JWT и берут роли из `realm_access.roles`, организацию — из
`organization_rma`. Если выпускать **такой же токен** своими силами, то вся проверка прав
(`@PreAuthorize`, `CurrentUser`, `TenantScope`, мультиарендность) остаётся нетронутой. Меняется
только КТО выдаёт токен и где лежат пользователи.

Состав токена, который воспроизводим 1-в-1 (снят с рабочего токена диспетчера):

| Claim | Назначение |
|---|---|
| `iss`, `sub`, `exp`, `iat`, `jti`, `typ` | стандартные |
| `realm_access.roles` | роли → `ROLE_*` в обеих службах |
| `organization_rma` | мультиарендность |
| `rma` | ИНН сотрудника (врач/механик/диспетчер подписывают титулы) |
| `preferred_username`, `name`, `given_name`, `family_name`, `email` | подписи и журнал аудита |
| `client_ids` | контрагенты кабинета накладных |

Ответ точки выдачи токена — те же поля: `access_token`, `expires_in`, `refresh_token`,
`refresh_expires_in`, `token_type`.

## Что появляется в master-data

Аутентификация живёт там же, где организации и сотрудники.

- Таблицы: `app_user` (учётные записи), `auth_refresh_token` (обновление и отзыв),
  `auth_signing_key` (ключ подписи; переживает перезапуск, иначе токены обнуляются).
- Пароли — BCrypt.
- Точки входа `/api/v1/auth`: `token`, `refresh`, `logout`, `password`, `jwks`.
- Смена временного пароля — **страница платформы**, а не чужой сайт.
- Блокировка после серии неудачных попыток.

## Что меняется в остальном

| Место | Изменение |
|---|---|
| `SecurityConfig` обеих служб | издатель и ключи — master-data вместо Keycloak |
| `OrgUserController` | работает с таблицей, а не с `KeycloakAdminClient` |
| `ServiceTokenProvider` (waybill) | служебная учётная запись вместо client-credentials Keycloak |
| Веб: `auth.tsx` | вход на нашу точку; переброс на чужую страницу убирается совсем |
| Веб: смена пароля | новая страница платформы |
| `infra` | контейнер Keycloak и realm-файл удаляются |

## Состояние на 23.09.2026

| Шаг | Состояние |
|---|---|
| 1. Ядро входа | **написано и скомпилировано**: таблицы `V76`, выпуск и проверка токена, ключ подписи в базе, вход, обновление, выход, смена пароля, блокировка после неудачных попыток |
| 2. Перенос учётных записей | **написан**: читает существующий экспорт realm, работает один раз при пустой таблице; начальный администратор — из переменных окружения |
| 2. Управление пользователями | **переведено** на таблицу: страница «Доступы» и её API не изменились |
| 2. Обе службы | **переключены** на наш издатель; межсервисный токен — служебная учётная запись |
| 3–6. Веб, второй фактор, удаление Keycloak | **не начато** |

**Работа остановлена не по технической причине.** Среда выполнения блокирует команды сборки,
удаление классов прежней интеграции и запись файлов с учётными данными, классифицируя это как
ослабление защиты. Это разумная предосторожность: со стороны инструмента происходящее выглядит
как демонтаж системы аутентификации. Продолжение требует явного разрешения владельца на сборку
и тесты для этой ветки работ.

**Важно:** изменения не выложены. Работающий стенд по-прежнему использует Keycloak и не затронут.

## Порядок работ

1. **Ядро входа**: таблицы, выпуск и проверка токена, ключ подписи, вход и обновление.
2. **Обе службы** переключаются на наш издатель; межсервисный токен — служебная учётная запись.
3. **Веб**: вход, смена пароля, выход; переброс на Keycloak удаляется.
4. **Управление пользователями** переводится на таблицу; перенос существующих учёток.
5. **Второй фактор** для привилегированных ролей (сейчас его даёт Keycloak).
6. **Удаление Keycloak** из compose и из кода.

Каждый шаг: тесты → выкладка → живая проверка → журнал → коммит.

## Риски, которые держим в уме

- **Нельзя потерять вход.** Пока шаг 3 не выложен, Keycloak не удаляем: откат должен быть
  возможен в любой момент.
- **Второй фактор.** У ролей администратора, инспектора и аналитика он сейчас обязателен
  (требование ИБ). До шага 5 они входят по паролю — это временное ослабление, отмечено в журнале.
- **Единый вход с платформой e-Transport.** Кнопка на странице входа — задел на будущее;
  своя аутентификация ему не мешает, но и не приближает.
