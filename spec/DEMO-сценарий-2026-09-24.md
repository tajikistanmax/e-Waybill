# Демонстрация заказчику 24.09.2026 — сценарий показа е-Роҳхат (ЭПД РТ)

> Документ для владельца: что открыть, под каким логином войти, что сказать и что должно
> получиться. Демо-данные создаёт скрипт `scripts/seed-demo-showcase.ps1` (данные — в
> `scripts/demo-showcase.json`). Реальные перенесённые записи старой системы он не трогает:
> все демо-организации помечены «(демо)», их РМА начинаются с `99240`, госномера — `xxxxDM01`.

---

## 1. Главное за одну минуту

- **Адрес:** http://localhost:3000 (он же http://localhost/). Проверка QR без входа: http://localhost:3002.
- **Пароль всех демо-логинов:** `Demo-Rohkhat-2026` (постоянный, менять при входе не нужно).
- **Утром, за 15 минут до показа**, один раз запустить (≈1 минута):
  ```
  cd D:\Projects\e-Waybill
  powershell -ExecutionPolicy Bypass -File scripts\seed-demo-showcase.ps1
  ```
  В конце должно быть **`Done without problems.`** и две таблицы: логины (у всех `SignIn OK`) и
  путевые листы на сегодня (38 штук, все в нужных статусах). Скрипт можно запускать сколько
  угодно раз — дубликатов не будет. Утренний запуск нужен, чтобы «сегодняшние» отчёты и
  GPS-мониторинг были свежими: вчерашние незакрытые демо-листы он сам закроет или аннулирует.
- **6 демо-перевозчиков** (город с 2 филиалами, такси, грузовой, междугородний, международный
  грузовой), в каждом — администратор, диспетчер, врач, механик, бухгалтер, заправщик (АЗС),
  2 водителя с логинами, ТС и водители без листов для живой выписки.

## 5. Сценарий показа (22 шага, ~60 минут)

Удобно держать открытыми два окна браузера: обычное и «инкогнито» (для второй роли).

### Блок А. Государство и компании

**1. Вход администратора Минтранса.** Логин `admin`.
Говорить: «Одна платформа на всю страну: Минтранс видит всех перевозчиков и все листы».
Ожидается: Главная панель со счётчиками по статусам; раздел «Компания» — 6 демо-перевозчиков
и перенесённые из старой системы организации.

**2. Компания с филиалами.** Выйти, войти `bus.admin`.
Говорить: «Головная компания видит оба своих парка, может сузить выборку до филиала».
Ожидается: в реестре путевых листов листы обоих филиалов (1101DM01 и 1201DM01); вверху —
переключатель филиала; «Транспорт и водители» — ТС и водители обоих парков.

**3. Выдача логина сотруднику.** Под `bus.admin`: «Доступы» → блок выдачи доступа:
«Сотрудник» — Холов Ориф Ғафурович (водитель, 9924011207), «Логин» — например `bus1.drv3`,
«Организация» — Автобусный парк №1 (филиал), «Роль» — Водитель → выдать.
Говорить: «Логины сотрудникам выдаёт сам перевозчик, чужую организацию выбрать нельзя;
администратор филиала выдаёт только в свой филиал».
Ожидается: система показывает временный пароль. Во втором окне войти этим логином —
откроется страница смены пароля, после смены — кабинет водителя.

### Блок Б. Полный цикл путевого листа (Автобусный парк №1)

**4. Диспетчер выписывает лист.** Войти `bus1.disp` → «Создать путевой лист».
Шаги мастера: тип **Т(1-АД) автобус** → ТС **1107DM01** и водитель **Холов Ориф** → маршрут
«№3 Шоҳмансур — 102 мкр» → «Создать путевой лист» → на карточке «Подписать Т1».
Говорить: «Система до выписки проверяет лицензию, техосмотр, права, медсправку, что на ТС и
водителя нет другого действующего листа».
Ожидается: статус «Ожидает осмотров».

**5. Врач.** Войти `bus1.doctor` → «Кабинет врача».
Ожидается: в очереди два водителя (Юсупов Фаррух — демо-лист 1104DM01, и Холов Ориф — только
что выписанный). «Начать осмотр» → давление/пульс/температура/алкотест → «Допустить».
Показать: «История осмотров»; у парка №2 (`bus2.doctor`) есть пример **недопуска**.

**6. Механик.** Войти `bus1.mech` → «Кабинет механика» → «Провести контроль» → чек-лист →
«Исправен — Допустить к рейсу».
Показать отказ: `cargo.mech` → журнал: ТС 3103DM01 не выпущено (износ тормозных колодок).

**7. Бухгалтер.** Войти `bus1.buh` → «Путевые листы» → лист в статусе «Ожидает оплаты»
(ваш и демо 1103DM01) → «Подтвердить оплату».
Говорить: «После оплаты система присваивает национальный номер и подписанный QR-код».
Ожидается: статус «Готов к выдаче», номер вида `01-26-04-0000xxx-x`.

**8. Выдача и выезд.** Снова `bus1.disp` → карточка листа → «Выдать водителю» →
«Т4 — выезд на линию».
Ожидается: статус «Активен».

**9. Пункт выдачи топлива.** Войти `bus1.azs` → «Пункт выдачи топлива» → лист → вид топлива
«Дизель», выдано 90 л, остаток при выезде 25 л → «Записать выдачу».
Говорить: «Заправщик видит только листы на заправке своей организации и не может менять сам лист».

**10. Водитель.** Войти `bus1.drv1`.
Ожидается: «Текущий путевой лист» с QR-кодом, маршрут, срок действия, положение на карте,
история рейсов (есть закрытый лист на 186 км).
Говорить: «Этот QR водитель показывает инспектору с телефона».

**11. Возвращение и закрытие с расчётом.** Любой лист «на линии». Грузовой (послерейсовый
медосмотр не нужен): `cargo.disp`, лист 3101DM01 (опасный груз) → одометр возврата (больше
одометра выезда), транспортная работа, число ездок → «Т5 — возвращение» → «Закрыть путевой лист».
Пассажирский (автобус, троллейбус, маршрутка, такси, 4М-БМ): после «Т5 — возвращение» войти
врачом (`bus1.doctor`) → «Кабинет врача» → блок **«Послерейсовый медосмотр (Т6)»** → «Начать
осмотр» → «Состояние в норме» (или с карточки листа кнопка «Провести послерейсовый медосмотр
(Т6)»); затем диспетчер → «Закрыть путевой лист».
Ожидается: статус «Завершён»; на карточке блок «Нормирование топлива» → кнопка расчёта:
пробег, норма на 100 км с коэффициентами, норма/факт в литрах, отклонение, стоимость рейса.
Готовые примеры закрытых листов с расчётом — в каждой компании (раздел 4). Пример
**перерасхода** — возвращённый лист 5Б-БМ 5103DM01 у Тоҷиктранс (выдано больше нормы).

**12. Печать и QR.** На карточке закрытого или активного листа → «Печатная форма».
Ожидается: бланк с реквизитами, таблица электронных подписей Т1–Т6, QR-код и штамп
«Подписано в системе». Отсканировать QR телефоном (или открыть ссылку) →
страница http://localhost:3002/verify/… «ПУТЕВОЙ ЛИСТ ДЕЙСТВИТЕЛЕН».

### Блок В. Все виды путевых листов

**13. Такси и легковой (3-С).** `taxi.disp` — реестр: такси на линии, легковой «хатсайр» готов,
почасовой возвращён и черновик. Живая выписка: 2106DM01 + Турсунов Далер, вид услуги
«Такси». Бухгалтер `taxi.buh`: на закрытом листе 2101DM01 — отметка кассы «выручка сдана».

**14. Грузовой 2-Б и накладная.** `cargo.disp` — лист 3101DM01 (цемент, закрыт) с прицепом и
накладной: отправитель, получатель, груз. Лист «на линии» — опасный груз, класс ADR 3.
Спецтехника 3104DM01 — учёт в моточасах (1240,5 → 1248).

**15. Междугородний и 4М-БМ.** `intercity.disp` — автобус Худжанд — Душанбе на линии; лист
4М-БМ Худжанд — Ташкент **с двумя водителями** готов к выдаче; закрытый 4М-БМ с числом
перевезённых пассажиров.

**16. Международный грузовой 5Б-БМ + CMR.** `intl.disp` — лист Душанбе — Алматы на линии, CMR с
отправителем и получателем. Живая выписка: 5103DM01 + Азимов Бахтиёр, страны
Таджикистан → Казахстан, дозвол `EP-2026-0003`, виза, город погрузки/разгрузки, груз, № ББА.
Внешние кабинеты: `intl.sender` («Накладные») видит только свои CMR;
`customs` — подтверждает CMR («Тасдиқ кардан»).

### Блок Г. Контроль и надзор

**17. Инспектор.** Войти `inspector` → «Кабинет инспектора» → поиск по госномеру `2101DM01`
(или «Сканировать QR») → карточка → «Заблокировать лист» → основание из списка, место, № акта.
Ожидается: статус «Заблокирован». Уже заблокированные примеры: 1105DM01 (неисправность),
4103DM01 (режим труда и отдыха). Раздел «Нарушения» — список блокировок.

**18. Разблокировка.** `admin` → карточка заблокированного листа → причина → «Разблокировать».
Говорить: «Снять блокировку может только Минтранс, перевозчик аннулировать заблокированный лист не может».

**19. GPS-мониторинг.** `bus.admin` или `admin` → «GPS-мониторинг».
Ожидается: 6 машин «на линии» на карте (Душанбе, трасса на Худжанд, Бохтар — Кӯлоб).

### Блок Д. Отчёты и настройки

**20. Отчёты за сегодня.** `bus.admin` → «Отчёты и аналитика» → «Сводка», период — сегодня.
Ожидается: листы обоих парков по статусам и типам, пробег, выданное топливо.

## 6. Что делать, если…

| Ситуация | Что делать |
|---|---|
| Скрипт в конце пишет `PROBLEMS` | Прочитать строки под ним. Чаще всего — стенд ещё не поднялся: подождать 1–2 минуты и запустить скрипт ещё раз (он доделает только недостающее). |
| «Неверный логин или пароль» | Проверить раскладку и пароль `Demo-Rohkhat-2026`. После 10 ошибок логин блокируется на 15 минут — войти другим логином той же роли или подождать. Можно заново запустить скрипт: он вернёт постоянный пароль. |
| После входа просит сменить пароль | Это логин, созданный вручную на демо (шаг 3) — так и должно быть. Для демо-логинов — запустить скрипт, он выставит постоянный пароль. |
| «На это ТС уже оформлен действующий путевой лист» | Взять свободную пару ТС/водитель из таблицы в разделе 4 или аннулировать свой пробный лист. |
| «Дозвол выдан для страны …, не заявленной в рейсе» | Взять номер дозвола нужной страны из раздела 4 (`EP-2026-0003` — Казахстан и т.д.) или добавить страну дозвола в транзит. |
| Закрытие автобусного/такси/маршрутного листа: «Требуется послерейсовый медосмотр (Т6)» | Войти врачом этой компании → «Кабинет врача» → блок «Послерейсовый медосмотр (Т6)» → «Начать осмотр» → «Состояние в норме». Затем снова «Закрыть путевой лист». |
| Закрытие отвечает «Служебная учётная запись недоступна» | В `infra/.env` нет `SERVICE_ACCOUNT_PASSWORD` или службы не перезапущены после его добавления (раздел 7). |
| Карта мониторинга пустая / «сигнал давно» | GPS-точки ставит скрипт — запустить его снова, точки обновятся. |
| Отчёт «за сегодня» пустой | Скрипт не запускался сегодня — запустить. |
| Сайт не открывается | `docker ps` — должны работать `epd-prod-web`, `epd-prod-master-data`, `epd-prod-waybill`, `epd-prod-postgres`. Если нет — раздел 7. |

## 7. Как поднять стенд с нуля

1. **Docker Desktop** запущен. В `infra/.env` заданы секреты стенда (в git не хранятся), в том
   числе обязательные `MEDDATA_ENCRYPTION_KEY` (ключ шифрования медданных — не менять на живых
   данных) и `SERVICE_ACCOUNT_PASSWORD` (служебная учётная запись: без неё не закрываются листы).
2. **Запуск стека** (локальная машина, порты API публикуются для скриптов):
   ```
   cd D:\Projects\e-Waybill\infra
   docker compose -p epd-rt-prod -f docker-compose.prod.yml -f docker-compose.local.yml up -d --build
   ```
   Образ MinIO берётся с **quay.io** (`quay.io/minio/minio`), потому что Docker Hub больше не
   отдаёт `minio/minio` — это уже прописано в `docker-compose.prod.yml`, делать ничего не нужно.
   Первый запуск со сборкой — 10–20 минут. Проверка: `docker ps`, сайт http://localhost:3000.
3. **Перенос данных старой системы** (нужен контейнер старой базы `rohkhattjralavel-db-1` с дампом
   из `D:\Projects\rohkhat.tj ralavel`). По порядку, из `scripts\migration`:
   ```
   powershell -ExecutionPolicy Bypass -File scripts\migration\run_phase1_2.ps1
   powershell -ExecutionPolicy Bypass -File scripts\migration\run_phase3.ps1
   powershell -ExecutionPolicy Bypass -File scripts\migration\run_phase2b_3b.ps1
   powershell -ExecutionPolicy Bypass -File scripts\migration\run_phase4.ps1
   powershell -ExecutionPolicy Bypass -File scripts\migration\run_phase5.ps1 -Window 2025-09-21
   ```
   Фазы 1–4 (справочники, организации, ТС, водители, устройства) — минуты; фаза 5 (архив
   путевых листов, ~570 тыс.) — дольше. Все фазы повторяемые. Если PowerShell пишет
   «Unexpected token» — файл сохранён без BOM: пересохранить в UTF-8 с BOM (так уже исправлен
   `run_phase5.ps1`).
4. **Демо-данные:** `powershell -ExecutionPolicy Bypass -File scripts\seed-demo-showcase.ps1`.
   Параметры: `-SkipWaybills` (только компании и логины), `-SkipVerify` (без итоговой проверки
   логинов), `-MdUrl`/`-WbUrl` (другие адреса API), `-AdminPassword` (если пароль admin другой).
5. **Проверка:** войти `bus1.disp` / `Demo-Rohkhat-2026` — в реестре 8 листов парка №1.
