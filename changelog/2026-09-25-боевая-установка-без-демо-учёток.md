# 2026-09-25 — Боевая установка без демо-учёток из репозитория

## Что изменилось
- `infra/docker-compose.prod.yml`: `AUTH_BOOTSTRAP_REALM_FILE` по умолчанию пустой — перенос
  учётных записей из `infra/keycloak/epd-realm.json` выключен.
- `infra/docker-compose.local.yml`: локальный стенд включает этот перенос явно.
- `infra/env.example`: `EPD_AUTH_ADMIN_*` — обязателен для боевого сервера; `AUTH_BOOTSTRAP_REALM_FILE`
  — только для демо-стенда.
- `infra/preflight.sh`: предупреждает, если перенос демо-учёток включён или не задан начальный
  администратор.
- `infra/DEPLOY.md` §6: учётные записи боевой установки; как отключить демо-учётки на стенде,
  который переводится из демо в промышленную эксплуатацию.

## Как было ДО
При первом запуске с пустой таблицей учётных записей платформа создавала все учётки из файла
`epd-realm.json`, который лежит в репозитории вместе с паролями: `admin`, `dispatcher`, `doctor`,
`company`… и QA-учётки `*-automation` без второго фактора. На боевом сервере это значило вход по
паролям, известным всем, у кого есть доступ к репозиторию. `admin` требует второй фактор, но
подключает его при первом входе — кто вошёл первым, тот и привязал свой телефон.

## Как стало
Боевая установка стартует с одним администратором из `infra/.env` (пароль в репозитории не
хранится, при первом входе — смена пароля и второй фактор). Остальных пользователей он заводит
в «Пользователи» и «Доступы». Демо-стенд и локальный стенд включают перенос демо-учёток явно.

## Почему
Найдено при подготовке ответа владельцу 25.09.2026 «что нужно, чтобы было готово к продакшену».

## Кто решил
Разработчик (Claude): безопасное значение по умолчанию для боевой установки; демо-режим — явным
включением.

## Как
`${AUTH_BOOTSTRAP_REALM_FILE:-}` вместо пути по умолчанию; путь — в `docker-compose.local.yml`.
На уже работающие базы не влияет: перенос выполняется только при пустой таблице учётных записей.

## Как проверено
`docker compose config`: боевой файл — `AUTH_BOOTSTRAP_REALM_FILE: ""`, с локальным дополнением —
путь к файлу. Локальный стенд не затронут (учётки уже есть).
