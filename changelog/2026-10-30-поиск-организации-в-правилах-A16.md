# 2026-10-30 — Поиск организации по названию при переопределении правил (A16)

## Что изменилось
В «Настройки → Правила», блок «Переопределения по организации», поле выбора
организации заменено с «ввести ИНН вручную» на поиск по названию/ИНН с
выпадающим списком.

## Как было ДО
Сверка 25.09.2026 (A16): «3-С на 30 дней для Душанбе — нужен список
организаций, какие именно это организации». Расследование 30.10.2026
показало: сам механизм (переопределение `max_validity_days` на уровне
конкретной организации) уже реализован и работает — поле `scopeKey` в форме
«Переопределения по организации» принимало готовый ИНН. Список организаций
Душанбе был не нужен владельцу как ВХОДНЫЕ ДАННЫЕ для меня — он мог бы сам
находить и подключать нужные организации через настройки, если бы знал их
ИНН наизусть или искал его отдельно в реестре. Единственная реальная
проблема — неудобный ввод (сырой текст, не поиск).

## Как стало
- Загружается список организаций (`md.organizations()`), поле ввода стало
  поиском по названию ИЛИ ИНН с выпадающим списком совпадений (до 20),
  аналогично паттерну поиска организации в «Пользователи платформы».
- Уже добавленные переопределения по организации показывают название рядом
  с ИНН (было — только ИНН).
- После добавления правила выбор организации сбрасывается, остальные поля
  (правило, значение) остаются — удобно быстро добавить то же правило
  нескольким организациям подряд (например, всем организациям Душанбе).

## Важная оговорка (для владельца, не блокер)
`PolicyResolver.effective()`: порядок приоритета — `VEHICLE_TYPE` >
`ORGANIZATION` > `NATIONAL`. Проверено 30.10.2026: сейчас на стенде НЕТ ни
одного правила `max_validity_days` на уровне `VEHICLE_TYPE` — переопределение
по организации сработает без конфликта. Если в будущем кто-то добавит общее
правило `max_validity_days` для типа «3-С» на уровне типа ПЛ, оно ПЕРЕБЬЁТ
переопределения по конкретным организациям (включая Душанбе) для той же
комбинации правило+тип — это текущая архитектура резолвера, не баг, но стоит
иметь в виду при дальнейшей настройке правил.

## Почему
Прямой запрос владельца 30.10.2026 — подтверждение, что самообслуживание
через настройки возможно, и устранение единственного реального препятствия
(неудобный ввод ИНН).

Находка сверки 25.09.2026 (A16); решение и подтверждение — владелец
