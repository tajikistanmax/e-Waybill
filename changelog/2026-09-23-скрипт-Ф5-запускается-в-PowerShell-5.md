# 2026-09-23 — Скрипт переноса архива путевых листов (Ф5) снова запускается в Windows PowerShell 5.1

## Что изменилось
Файл `scripts/migration/run_phase5.ps1` сохранён с отметкой кодировки UTF-8 (BOM). Содержимое
не менялось.

## Как было ДО
Все остальные скрипты переноса (`run_phase1_2`, `run_phase3`, `run_phase2b_3b`, `run_phase4`)
сохранены с BOM, а `run_phase5.ps1` — без. Windows PowerShell 5.1 читает такой файл в кодировке
ANSI: русские строки в `Write-Host` превращаются в «кавычки-ёлочки», и разбор скрипта падает
(`Отсутствует завершающий символ "` — строки 159–162). 23.09 в 22:07 восстановление данных
legacy прошло фазы 1–4, а фаза 5 (архив путевых листов, ~2 млн) завершилась через секунду с
`exit=1` — архив не загрузился, отчёты за 2025-09…2026-08 пусты.

## Как стало
Скрипт разбирается PowerShell 5.1 без ошибок (`Parser.ParseFile` — 0 ошибок) и может быть
запущен тем же способом, что и остальные фазы.

## Почему
Без архива нет данных для показа отчётов за прошлые периоды на демонстрации.

## Кто решил
Владелец 23.09.2026: «доведи платформу до запуска к демонстрации»; руководитель поручил проверить
лог восстановления. Найдено агентом Claude (блок «путевые листы, расчёты, печать, отчёты»).
Сам перезапуск фазы 5 этим агентом не выполнялся (запуск на общем стенде оставлен руководителю).

## Как
Добавлены три байта `EF BB BF` в начало файла.

## Как проверено
`[System.Management.Automation.Language.Parser]::ParseFile(...)` под `powershell.exe` 5.1 —
0 ошибок разбора (до правки — ошибка на строке 159).
