# 2026-09-23 — Повторяемый живой прогон «роли, кабинеты, доступы, филиалы» + демо-филиалы компании

## Что изменилось
- **Автотест** `apps/web/e2e/roles-cabinets.spec.ts` (Playwright, 36 проверок) и обёртка
  `scripts/e2e-roles-cabinets.ps1` (`-Only carrier|cabinets`, `-Shots <папка>`). Прогон идёт по
  живому стенду и оставляет скриншоты каждой страницы и JSON-отчёт замечаний.
  1. «Новый перевозчик»: администратор платформы находит компанию поиском и выдаёт ей
     администратора (логин = телефон, временный пароль показан один раз) → вход → смена пароля на
     `/auth/password` через интерфейс → администратор компании видит компанию и филиал
     (переключатель филиала) → выдаёт логины администратору филиала, диспетчеру, врачу, механику,
     бухгалтеру, АЗС и водителю (водитель — по записи водителя) → каждый входит, меняет пароль,
     попадает в свой кабинет; проверяются меню и область данных → отключение / включение / сброс
     пароля / смена роли / удаление → блокировка после 10 неудач → плановое обновление токена в
     браузере и выход, гасящий токен обновления. Тестовая компания `990000500` и филиал `990000501`
     создаются и удаляются самим тестом.
  2. 14 демо-логинов: каждый пункт меню и 88 подстраниц (настройки, справочники, реестры, отчёты,
     парк, «Компания», «Доступы») — без 4xx/5xx API, ошибок консоли, непереведённых ключей и
     перенаправлений; компания заводит водителя в филиал, находит и удаляет; компания ведёт свой справочник маршрутов (создать → найти → изменить без дубля → удалить); матрица на странице
     «Роли» реально меняет меню (и возвращается обратно).
- `.gitignore`: папка скриншотов по умолчанию `apps/web/e2e-shots/`.
- **Данные стенда (не в git, только локальный стенд)**, через API администратора платформы:
  - у демо-компании `025680800` (логин `company`) заведены филиалы `100002091` «Филиал «Юг» (демо)»
    (логин `branch` — его администратор) и `100002092` «Филиал «Север» (демо)»;
  - логин `fuel` (пункт выдачи топлива) перенесён из несуществующей организации `100002000` в
    `025680800` (удалён и заведён заново с той же ролью и РМА `777777777`, пароль прежний).

## Как было ДО
- Сквозного теста «новый перевозчик» не было; прежние Playwright-тесты (`e2e/fixtures.ts`) входят
  паролем, равным логину, и после смены паролей демо-логинов не проходят.
- После восстановления перенесённых данных организаций `025680800`, `100002000`, `100002091` на
  стенде не было; филиал `100002091` раньше был подчинён `100002000`, а не `company` (`025680800`),
  поэтому сценарий «компания видит свои филиалы» демо-логинами не воспроизводился (AUDIT A7).
- Кабинет `fuel` был пуст: его организация `100002000` не совпадала с парком демо-компании
  (AUDIT, находка 15), а после восстановления данных её не стало вовсе.

## Как стало
- Под `company`: `/organizations` → `025680800, 100002091, 100002092`; под `branch` → `100002091`.
- Под `fuel`: `/fuel-station/waybills` → 200, 5 листов демо-компании.
- Полный прогон `scripts/e2e-roles-cabinets.ps1` (23.09, ~00:10): **35 из 35**, замечаний в отчёте — **0**;
  отдельно тест справочника маршрутов — 1/1. (Ранее единственным замечанием был `422` на
  `/reports/passenger-volume-trend` на главной администратора и аналитика — его закрыл агент области отчётов.)

## Почему
Задача 23.09 (показ 24.09): проверить вживую от и до роли, кабинеты, доступы, компании и филиалы,
сохранить повторяемый прогон.

## Кто решил
Владелец 23.09: «доведи платформу до запуска к демонстрации». Правка демо-данных — локальные
тестовые данные, разрешено поручением; сделана только через API (прямой доступ к базе не нужен).

## Как
Playwright 1.62 (Chromium), `workers=1`; вход — через форму `/login`; область данных —
через API `/api/v1/auth/token` + `/organizations`, `/org-users`, `/drivers`. Обёртка вызывает CLI
Playwright через `node` (шим `npx` на Windows портит аргументы не-ASCII и `|`).

## Коммиты (ветка `migration`)

## Как откатить

  необходимости переносится обратно так же — удалить и завести в нужной организации.
