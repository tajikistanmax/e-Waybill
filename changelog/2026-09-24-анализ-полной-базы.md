# 2026-09-24 — Анализ всей базы старой платформы: какие поля форм убрать

## Что изменилось
Добавлен документ `spec/АНАЛИЗ-полной-базы-старой-платформы-2026-09-24.md` и повторяемый скрипт
`scripts/field-usage-legacy-all.ps1`. Разобраны все рабочие таблицы старой базы, кроме четырёх
форм, разобранных раньше (компания, ТС, водитель, сотрудник):
- путевые листы 1-АД, 1-А, 3-С, 2-Б, 5Б-БМ, 4-МБМ, их рабочие дни и строки топлива;
- накладные (борхат) и CMR, маълумотнома;
- 30 справочников.

Для каждого столбца посчитана заполненность (всего, у активных, без заглушки «1», за последние
3 месяца), с разбивкой по видам и по ключам внутри JSON. Каждое поле сопоставлено с новой
платформой: где его вводят (файл и строка) и кто его читает (расчёт, проверки, печать, отчёты).
Итог — единый список кандидатов на удаление из форм: 14 пунктов первой очереди и 17 второй.

Код платформы и настройки **не менялись**: поля убирает руководитель по списку.

## Как было ДО
Статистика использования была только по четырём формам (`spec/АНАЛИЗ-полей-по-боевой-базе-2026-09-24.md`).
Какие поля путевых листов, накладных, справки и справочников реально заполнялись в старой
платформе, было неизвестно.

## Как стало
Есть документ с ответом по каждому полю и готовый список «что убрать» с файлами и строками.
Главные выводы:
- **не использовались целиком:** 4-МБМ (0 листов за всё время), CMR (4 записи за всё время),
  касса 3-С (0 за год), экспедитор в накладной (9 из 153 588);
- **топливо вели только автобусы 1-АД**; «норма к выдаче» и «надбавка ниже 0 °C» — 0 %;
- **найдена ошибка:** в мастере создания ПЛ списки «Самт», «Заказчик» (2-Б) и «Тип маршрута»
  всегда пустые — загрузка справочников потерялась при слиянии `29b25e8`. В старой базе «Самт» и
  «Заказчик» заполнены у 100 % грузовых листов.

## Почему
Владелец 24.09.2026: «изучи полностью базу данных старой платформы: какие поля там не заполнены
/ не используются — и в новой платформе их логично убрать».

## Кто решил
- **Задача** — владелец.
- **Распределение работы** — руководитель: этот агент разбирает все таблицы, кроме четырёх форм.
- **Метод** — разработчик (Claude): активные за 12 месяцев, без заглушек, по видам. Метод тот же,
  что у первого анализа, плюс разбор JSON-полей.
- **Сами поля не трогали:** удаление полей из форм меняет работу всех пользователей и частично
  печать, поэтому его делает руководитель по списку.

## Как
Скрипт читает локальную копию старой базы (контейнер `rohkhattjralavel-db-1`, MySQL). Порядок работы:
1. Активные строки копируются во временную схему `field_usage`.
2. Для каждого столбца одним проходом считается заполненность, затем число разных значений и
   самое частое значение.
3. JSON-поля раскладываются на ключи через `JSON_TABLE`: рабочие дни, строки топлива, зоны,
   транзит, нормы марок.
4. В конце схема удаляется. Таблицы старой базы только читаются.

Сопоставление с новой платформой сделано по коду: веб-формы, Flyway-миграции, `WaybillService`,
`calc/*`, `FuelCalculationService`, шаблоны печати, веб-печать.

  ошибок SQL. Служебная схема удалена (`SHOW DATABASES` — `field_usage` нет).
- Скрипт — чистый ASCII, разбирается парсером PowerShell 5.1 без ошибок.
- Выборочные числа перепроверены отдельными запросами:
  - доля листов 2-Б с накладными;
  - последняя отметка кассы 3-С;
  - последняя запись CMR;
  - виды транспорта справок;
  - «График» 1-АД по месяцам.
- Отсутствие загрузки списков в `new/page.tsx` проверено по коду и по истории git
  (`926ee6a` → `29b25e8`).
- Не проверено: сколько новых листов в базе новой платформы заполнили эти поля — запрос к ней в
