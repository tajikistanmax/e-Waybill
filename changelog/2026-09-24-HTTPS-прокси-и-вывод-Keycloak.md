# 2026-09-24 — HTTPS через обратный прокси, заголовки безопасности; Keycloak убран из стека

## Что изменилось
Перед платформой поставлен обратный прокси nginx (`infra/nginx`): снаружи теперь открыт только
он — HTTPS 443 (платформа), 8443 (портал проверки QR), 80 (перенаправление на HTTPS). Прокси
добавляет заголовки безопасности и политику CSP, ограничивает частоту запросов к входу и
передаёт службам подлинный IP клиента. Контейнер Keycloak убран из стека. Написана инструкция
выкладки на стенд `infra/DEPLOY.md`.

Файлы:
- `infra/nginx/` (новый): `Dockerfile`, `templates/epd.conf.template`, `snippets/tls.conf`,
  `snippets/proxy.conf`, `snippets/security-headers.conf`, `15-epd-tls-cert.sh`;
- `infra/docker-compose.prod.yml` — сервис `proxy`; у `web` и `public` порты наружу не
  публикуются; сервис `keycloak` удалён; адрес портала проверки QR — `https://<EPD_TLS_HOST>:8443`;
- `infra/docker-compose.local.yml` — локально открывает 3000/3002/8081/8082 для автотестов;
  переопределения Keycloak удалены;
- `infra/docker-compose.yml` (dev) — сервис `keycloak` удалён;
- `apps/web/Dockerfile` — убран неиспользуемый `NEXT_PUBLIC_KEYCLOAK_URL`;
- `apps/web/playwright.config.ts` — `ignoreHTTPSErrors` (автотесты через прокси с самоподписанным сертификатом);
- `packages/shared/lib/i18n.tsx` — описание входа в Настройки → Безопасность (было «Keycloak OIDC»);
- `infra/DEPLOY.md` (новый), `CLAUDE.md` (раздел о выкладке), `.gitattributes` (новый: LF для
  скриптов контейнеров), `.gitignore` (`infra/nginx/certs/`).

## Как было ДО
- Платформа открывалась по `http://10.10.29.70` — без шифрования: пароли, токены и
  персональные данные водителей шли по сети открытым текстом.
- Наружу были опубликованы web (80 и 3000), портал проверки (3002) и Keycloak (8180), хотя
  Keycloak с 23.09 ни одной службой не использовался (вход — в самой платформе).
- Заголовков безопасности (CSP, запрет встраивания в чужие страницы, nosniff и т.д.) не было;
  ответы раскрывали `X-Powered-By: Next.js`.
- Сканер QR инспектора на телефоне не работал: камера в браузере доступна только по HTTPS.

## Как стало
- `http://…` → 301 на `https://…`. TLS только 1.2 и 1.3 (TLS 1.1 отвергается).
- Сертификат: настоящий кладётся в `infra/nginx/certs/` (`tls.crt` + `tls.key`); если его нет,
  прокси сам создаёт самоподписанный на `EPD_TLS_HOST` — для пилота во внутренней сети.
- Заголовки на всех ответах: `Content-Security-Policy` (скрипты, стили, картинки, запросы —
  только свои; встраивание платформы в чужие страницы запрещено), `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` (камера — только
  своему сайту), `Cross-Origin-Opener-Policy`. HSTS — включается переменной `EPD_HSTS` только с
  настоящим сертификатом. `X-Powered-By` скрыт.
- Вход (`/auth/token`, `/auth/second-factor`, `/auth/password`): не больше 60 запросов в минуту
  с одного IP (всплеск 60) — вторая линия защиты от подбора поверх блокировки учётки.
- Службы видят настоящий IP клиента: прокси перезаписывает `X-Forwarded-For` (клиент не может
  подставить свой и обойти ограничение частоты или подменить IP в журнале аудита).
- Keycloak: контейнера нет, порт 8180 закрыт. Экспорт realm остаётся — из него master-data один
  раз переносит учётки при установке с нуля. Классы прежней интеграции в коде пока остаются
  (выключены, ни одного обращения) — удаляются отдельным шагом.

## Почему
Вердикт готовности 24.09: без HTTPS и заголовков безопасности платформа не может идти в
промышленную эксплуатацию (ТЗ ИБ-13: защита каналов связи, персональные данные). Keycloak —
лишний открытый порт и лишний компонент без обновлений безопасности.

## Кто решил
Владелец 24.09.2026: «начинай, приготовь платформу к пилоту и продакшену». Решения по
устройству прокси — разработчик (Claude).

Спорные решения:
- **`'unsafe-inline'` для скриптов в CSP.** Next.js встраивает служебные скрипты в страницу;
  строгая CSP с одноразовыми метками (nonce) требует отключить статическую отдачу всех страниц.
  Внешние скрипты CSP всё равно запрещает. Ужесточение — отдельная задача.
- **Портал проверки QR на отдельном порту 8443**, а не по пути на 443: у него своя сборка со
  своими `/_next/*`, на общем адресе они конфликтуют.
- **Ссылки старых тестовых QR на `:3002` перестают открываться.** Боевых QR новая платформа
  ещё не выдавала (боевая система — старая rohkhat.tj), поэтому переадресацию не делали.
- **Самоподписанный сертификат по умолчанию**: стенд во внутренней сети по IP, сертификат
  публичного УЦ на IP не выдаётся. Для прода — сертификат УЦ (DEPLOY.md, раздел 3).

## Как
nginx 1.27 (alpine) + openssl; шаблон подставляет только переменные `EPD_*`
(`NGINX_ENVSUBST_FILTER`); сертификат создаёт скрипт `/docker-entrypoint.d/15-epd-tls-cert.sh`,
если файлов нет. Заголовки заданы только на уровне `server` (nginx не наследует `add_header`
в `location`, где есть свой).

## Как проверено
- `docker compose config`: в боевой конфигурации наружу публикуются только 80, 443, 8443.
- `curl`: `http://localhost/login` → 301 на `https://localhost:443/login`; `https://localhost/login`
  → 200 со всеми заголовками, без `X-Powered-By`; `https://localhost:8443/` → 200; TLS 1.1 — отказ.
- Обход всех 14 демо-кабинетов и всех пунктов меню через `https://localhost` (Playwright,
  `roles-cabinets.spec.ts`): 23 из 24 без единой ошибки в консоли — CSP ничего не ломает.
  Одна находка — непереведённое событие журнала `TOTP_ENROLL` (исправлено отдельным коммитом).
- Контейнер Keycloak удалён (`--remove-orphans`), вход и все проверки работают без него.
