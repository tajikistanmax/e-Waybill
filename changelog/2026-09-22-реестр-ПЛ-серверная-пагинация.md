# 2026-09-22 — Реестр ПЛ: серверная пагинация и фильтры в SQL (MIGRATION.md §8.4)

## Что изменилось
- **waybill-service**: `GET /api/v1/waybills/page` — страница реестра с сервера (`page`, `size` ≤ 1000, сортировка
  «новые сверху») и полным набором фильтров в SQL: `organizationRma`, `status`, `type`, `vehicle` (госномер, точно),
  `driver` (РМА основного/второго водителя либо часть ФИО из снимка), `svc` (вид обслуживания 3-С: `serviceKind`
  живых ПЛ или числовой `typeService` мигрированных), `docKind` (`attachment` — 2-Б/ОГ с заполненной накладной,
  `cmr` — 5Б-БМ с СМР), `client` (часть названия отправителя/получателя/экспедитора/заказчика из накладной),
  `from`/`to` (по дате начала действия, иначе создания), `q` (№ ПЛ, госномер, РМА водителя/компании, ФИО, название
  компании), `archived` (архив source=MIGRATED только по явному запросу). Ответ `{content, page, size, totalElements,
  totalPages}`. Новый `WaybillRegistryService` (JPA `Specification`, JSON-поля через `jsonb_extract_path_text`),
  `WaybillRepository` расширен `JpaSpecificationExecutor`.
- `GET /api/v1/waybills/status-counts` — число ПЛ по статусам в области вызывающего без архива (карточки-счётчики).
- Область видимости — как у прежнего листинга: тенант (компания + филиалы) из токена, водитель — только свои ПЛ,
  платформенные роли — все организации с необязательным `organizationRma`.
- **Web** `/waybills`: данные страницы и счётчики — с сервера; фильтры ТС/водитель/клиент стали текстовыми
  (серверный отбор), добавлен флажок «Показывать архив»; текстовые поля с дебаунсом 250 мс; экспорт CSV — по текущему
  отбору с сервера, до 1000 строк; страница — 20 строк. Прежний `GET /api/v1/waybills` (кэп 1000) не тронут — его
  используют другие кабинеты.

## Как было ДО
Legacy: все реестры (Waybill1ad/1a/3c/2b/5bbm, CMR, борхаты) — Backpack DataTables с серверной пагинацией и фильтрами.
В e-Waybill реестр грузил до 1000 ПЛ без архива одним запросом и фильтровал/листал их в браузере: при >1000
ПЛ в области часть просто не показывалась, а счётчики считались по обрезанному списку.

## Как стало
Реестр отдаёт точное общее число и любую страницу по фильтрам в SQL; счётчики — агрегат по БД; архив доступен
флажком.

## Почему
MIGRATION.md 8.4 — последняя открытая строка §8 (пользователь особо подчёркивал списки/фильтры).

## Кто решил
Агент Claude по промпту Шага 2. Решения: селекты ТС/водителя/клиента заменены текстовым отбором (варианты
для селектов брались из загруженного списка — с серверной пагинацией их не из чего строить, а полные справочники
для платформенных ролей — тысячи записей); экспорт ограничен 1000 строк (как прежний кэп).
