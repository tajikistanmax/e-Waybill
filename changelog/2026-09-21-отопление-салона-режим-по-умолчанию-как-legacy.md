# 2026-09-21 — Пассажирский расчёт: надбавка на отопление салона выключена по умолчанию (паритет с legacy), режим — настройкой (MIGRATION.md §5.3)

## Что изменилось
- Новый режим `epd.calc.interior-heating` (`CALC_INTERIOR_HEATING`): `OFF` (по умолчанию) / `WINTER` / `ALWAYS` —
  enum `InteriorHeatingMode`.
- `WaybillCalcEngine.passenger` передаёт в норму `brands.fuel_interior_heating × часы работы` только когда режим
  разрешает: `OFF` — никогда; `WINTER` — только при действующем зимнем коэффициенте маршрута; `ALWAYS` — круглый год
  (прежнее поведение). Ветка Душанбе (`routes.excluding_coef`) не затронута — там отопление берётся из
  `routes.heating_fuel`, как в оригинале.
- Конструктор движка для тестов/ручной сборки (3 аргумента) даёт `OFF`; Spring-конструктор читает свойство.
- Тесты `WaybillCalcEngineTest`: `interiorHeatingOffByDefault`, `interiorHeatingWinterOnly`, `interiorHeatingAlways`,
  `interiorHeatingDoesNotTouchDushanbeBranch`.

## Как было ДО
В оригинале (`helpers.php:348`) надбавка `warm_salon = brand.fuel_interior_heating × work_time/60` закомментирована
и **никогда не применяется** (`warm_salon = 0`); по замыслу авторов она стояла внутри зимнего блока. В e-Waybill
(перенос из rohkhat-v2) надбавка была «восстановлена» и применялась **круглый год** для любой марки с заполненным
`fuel_interior_heating`. В боевом справочнике таких марок 4 (МАЗ 103 — 2.5 л/ч, ЛиАЗ 5292 — 3.0, Акиа Granbird — 2.5,
id 16 — 2.0): для их ПЛ на обычных (не душанбинских) маршрутах норма завышалась на 16–24 л за 8-часовую смену даже
летом. Live до правки: ПЛ автобуса «Акиа» 200 км, 8 ч, сентябрь → норма 88.0 л вместо 68.0 (legacy).

## Как стало
По умолчанию норма совпадает с legacy (надбавки нет). Владелец может включить надбавку без правки кода: `WINTER` —
как задумано в оригинале (только в зимний период маршрута), `ALWAYS` — как было в e-Waybill до 21.09.

## Почему
Пункт 5.3 MIGRATION.md (спот-чек ветки Душанбе `excluding_coef`): сама ветка А совпала 1-в-1
(`0.01·(fuel_100_dushanbe + additional_fuel_100 + additional_fuel)·L + cond_fuel + heating_fuel`, тест
`WaybillCalcEngineTest.excludingCoefBranch` = 64 л), но при сверке ветки Б обнаружилось расхождение чисел с legacy
по отоплению салона. Правило промпта: расхождения с оригиналом, которые не являются исправлением бага legacy, не
переносятся молча; неясные — безопасный вариант + вопрос владельцу (Вопрос 19).

## Что осталось осознанным расхождением (зафиксировано в 5.3 / Вопрос 9)
- **Кондиционер (ветка Б):** в legacy `helpers.php:379` из-за приоритета `?:` надбавка равна `cond_h / work_h` —
  безразмерная доля времени, ≤ 1 «л» (баг, а не ноль, как записано ранее в Вопросе 9). e-Waybill применяет
  корректную формулу из закомментированной строки 378: `(cond_h/work_h) · air_conditioner% · 0.01 · fuel · L`.
  Баг не переносится (правило промпта), точная legacy-формула сохранена как `conditionerFuelLegacy` для
  исторической сверки. Влияет только на ПЛ с заполненными часами кондиционера и `% кондиционера` у ТС.

## Кто решил
Агент Claude по правилу промпта «неясно → безопасный вариант + Вопрос к Максу»: безопасный = числа legacy
(`OFF`), выбор режима оставлен владельцу настройкой. Владелец — постановка «перенести 1-в-1».

## Как проверено
- `WaybillCalcEngineTest` (4 новых): OFF → 68.82 (как `normal`); WINTER → декабрь 88.82 (+2.5·8), июль 65.72 (без
  надбавки, K=6); ALWAYS → июль 85.72; Душанбе при ALWAYS → 64 (не зависит).
- Полный `:waybill-service:test`: **246 = 244 ✅ + 2 Testcontainers-окружение** (известное ограничение Docker
  Desktop, не регрессия). Web не менялся.
- **Live (локальный стек), один и тот же ПЛ `f4911f27…` (0114TJ01 «Акиа» Granbird 34 л/100 км, маршрут org без
  коэффициентов → K=0, 200 км, рабочий день 08:00–16:00 = 8 ч, выдано 100 л):** до правки норма **88.0 л**
  (68 + 2.5·8 отопление в сентябре), остаток 12.0; после деплоя (`OFF`) — **68.0 л**, остаток 32.0 = ручной расчёт
  по legacy `0.01·34·200·1.0`. Совпало.
