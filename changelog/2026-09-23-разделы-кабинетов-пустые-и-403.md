# 2026-09-23 — Разделы кабинетов: пустые страницы и отказы 403 из меню

## Что изменилось
Проход по каждому пункту меню всех 14 демо-логинов (Playwright, скриншоты) нашёл пункты, которые
вели на пустой экран, отказ сервера или перебрасывали на главную. Исправлено:
1. **«Компания» у администратора компании и филиала** — вместо пустого экрана раздел «Моя
   компания»: реквизиты своей организации, филиалы с числом ТС/водителей/сотрудников/доступов,
   переходы в парк и «Доступы»; администратор компании правит расчётные параметры (доля дохода,
   надбавки за класс) — ровно то, что ему разрешает бэкенд.
2. **Прямой заход и обновление страницы** (F5) на раздел, разрешённый матрицей ролей, больше не
   перебрасывает на главную: гвард разделов ждёт загрузки матрицы.
3. **«GPS-мониторинг» администратора филиала** — сервер отвечал 403 на `/gps/live` и
   `/gps/events` (пункт в меню есть, роль в `@PreAuthorize` — нет). Область сужает `tenantScope`.
4. **Отчёты инспектора** — каждая вкладка отчётов запрашивала каталог типовых разрезов
   (`/reports/types`), закрытый инспектору, — 403 в каждой странице. Каталог нужен только вкладке
   «Типовые» и запрашивается только там.
5. **Страница «Роли»**: после «Сохранить» нельзя было вернуть только что сделанную правку —
   кнопка оставалась неактивной до перезагрузки (сравнение шло с состоянием на момент открытия).

## Как было ДО
1. `company/page.tsx` рисовал реестр организаций только `SYSTEM_ADMIN`, остальным — `return null`,
   а матрица `role_access` (V20/V41) даёт `COMPANY_ADMIN` и `BRANCH_ADMIN` пункт «Компания» как
   профиль своей организации. Итог — пункт меню на пустую страницу (скриншоты `branch_company`,
   `company_company`). Отдельного места, где администратор компании видит свою компанию и
   филиалы, не было (только переключатель филиала в шапке).
2. `shell.tsx` решал «пускать ли» по запасному списку из `lib/roles.ts`, пока матрица из БД не
   загружена. У `COMPANY_ADMIN` в запасном списке нет «Компании» — при открытии `/company` по
   ссылке или F5 его мгновенно уводило на `/dashboard` (Playwright: «открылось /dashboard»).
3. `GpsController.live/events`: `hasAnyRole('DISPATCHER','COMPANY_ADMIN','SYSTEM_ADMIN',
   'INSPECTOR','MINTRANS_ANALYST')` без `BRANCH_ADMIN` — у администратора филиала мониторинг пуст
   и в консоли 403.
4. `ReportsView.tsx` на каждой вкладке звал `/reports/types` (класс `ReportController` без
   `INSPECTOR`) — у инспектора 403 на «Сводке».
5. `settings/roles/page.tsx`: `dirty()` сравнивал черновик со списком, загруженным при открытии.

## Как стало
Повторный проход Playwright по 14 логинам + 88 подстраницам (настройки, справочники, реестры,
отчёты, парк, «Компания», «Доступы»): ни одного перенаправления, пустой страницы, непереведённого
ключа, ошибки консоли; из отказов API остался один — `passenger-volume-trend` 422 на главной
администратора и аналитика (объём, область отчётов — см. отчёт). Под `branch` `/gps/live` → 200.
Матрица ролей: «GPS-мониторинг» у бухгалтера включён через страницу «Роли» → пункт появился в меню
бухгалтера; снят тем же интерфейсом → исчез.

## Почему
Показ заказчику: каждый пункт меню каждой роли должен открывать рабочую страницу.
