# 2026-09-21 — Груз: сквозной номер «Рамз» (`cargos.number`) в справочнике, снимке накладной и печати борхата (MIGRATION.md §2.25)

## Что изменилось
- master-data, миграция `V65__cargo_number.sql`: колонка `cargo.number BIGINT NOT NULL UNIQUE`, выдаётся
  последовательностью `cargo_number_seq` (default `nextval`); существующие грузы пронумерованы по порядку id.
  `Cargo.number` — только на чтение (`@Generated`, БД присваивает при вставке); API `GET/POST /dictionaries/cargos`
  возвращает `number`.
- waybill-service: `POST /waybills/{id}/consignment` принимает `cargoNumber` (снимок сквозного номера, рядом с
  `cargoId`/`cargoName`) → `typeData.cargoNumber`; печать борхата (`print-attachment.pdf`) выводит колонку «Рамз»
  (`WaybillPrintService.cargoNumberOf`: `typeData.cargo.number` → `typeData.cargoNumber` → «—»).
- Web: справочник грузов (`/dictionaries/cargos`) — первая колонка «Рамз (№ груза)»; в накладной ПЛ при выборе груза
  из справочника номер снимается автоматически (поиск и по номеру), в подсказке показывается «Рамз N». i18n ru/tj.
- Тест `WaybillPrintServiceCargoNumberTest` (3): приоритет снимка груза; снимок накладной (в т.ч. `42.0` → «42»);
  прочерк.

## Как было ДО
В legacy `App\Models\Cargo::creating` присваивал `number = max(number) + 1` (сквозной по всей таблице), а бланки
борхата печатали его: прил. 1 (`bill2b_attachment1`, колонка 12) и прил. 2 (`bill2b_attachment2`, «Рамз» рядом с
наименованием). В e-Waybill поле не переносилось (Javadoc `Cargo`: «только для отображения») — на бланке номера не было.

## Как стало
Каждый груз справочника получает сквозной номер от БД (гонок нет, в отличие от legacy max+1), номер виден в
справочнике и в подсказке выбора, снимается в накладную ПЛ и печатается в борхате в колонке «Рамз».

## Почему
MIGRATION.md 2.25 — поле бланка (Шаг 1: «number у cargo — обязателен», 12.15), без него борхат не соответствует
образцу.

## Кто решил
Агент Claude по промпту Шага 2. Отличие от legacy: номер выдаёт sequence БД, а не `max+1` в приложении
(та же семантика, без гонки).
