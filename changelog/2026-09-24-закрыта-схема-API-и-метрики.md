# 2026-09-24 — Закрыты схема API master-data и служебные метрики

## Что изменилось
- `infra/docker-compose.prod.yml`: master-data получил `DOCS_OPEN: ${DOCS_OPEN:-false}` — как у waybill.
- `infra/nginx/templates/epd.conf.template`: снаружи из служебных точек `/actuator/*` обеих служб
  доступна только `health`; метрики и остальное — 404.

## Как было ДО
- У waybill схема API (Swagger / OpenAPI) в боевой конфигурации закрыта (`DOCS_OPEN=false`),
  а у master-data переменная не была задана, и действовало значение службы по умолчанию —
  `true`. Через прокси и перенаправление web `https://<стенд>/md-api/v3/api-docs` и
  `/md-api/swagger-ui` отдавали полное описание API справочников **анониму** (проверено: 200).
- `/md-api/actuator/metrics` и `/wb-api/actuator/metrics` были доступны любому вошедшему
  пользователю, включая водителя (внутренние показатели служб).

## Как стало
- Схема API обеих служб — только после входа (анониму 401).
- Метрики снаружи — 404; `health` открыт (его показывает карточка «Состояние систем» на главной
  панели администратора). Проверки состояния на сервере — изнутри сети compose (DEPLOY.md).

## Почему
Подготовка к продакшену 24.09.2026. Описание всех точек API облегчает атаку; метрики раскрывают
внутреннее устройство и нагрузку.

## Кто решил
Владелец — задача «приготовь к продакшену»; находка и решение — разработчик (Claude).

## Как
Переменная окружения в compose; в nginx два `location ~`: сначала `^/(md|wb)-api/actuator/health$`
(проксируется), затем `^/(md|wb)-api/actuator(/|$)` → 404 (nginx берёт первое совпавшее выражение).

## Как проверено
`curl` через `https://localhost`: `md-api/v3/api-docs` 200 → 401, `md-api/swagger-ui` → 401,
`md-api/actuator/metrics` и `wb-api/actuator/metrics` → 404, `health` обеих служб → 200;
smoke-test 35/35, матрица прав 27/27.
