# 2026-09-22 — Госномер легкового ТС: строгий формат legacy 234AB01 / 1234AB01 (MIGRATION.md §12.2)

## Что изменилось
- **master-data** `VehicleCardRules.assertPlateFormat(transportType, number)`: для вида ТС «легковой» (тип 4, формы 3-С)
  госномер после канонизации (верхний регистр, без пробелов по краям) обязан соответствовать
  `^\d{3,4}[A-Z]{2}\d{2}$`; иначе 422 с текстом legacy (ru + tj). Вызывается в `POST /api/v1/vehicles` (карточка ТС
  из кабинета/админки). Прочие виды ТС (автобусы, грузовые, прицепы, микроавтобусы) — как в legacy, формат не
  проверяется (общая маска «буквы/цифры 4–20» осталась).
- **Web**: форма ТС (Компания → Транспорт) подставляет HTML-`pattern`/подсказку `1234AB01` при выборе вида «легковой».
- Канал единой платформы (`/sync/vehicle`, номер приходит из ГАИ) не трогается.

## Как было ДО
Legacy `ParkingRequest::withValidator`: **только при `transport_type_id == 4`** — 8 символов «4 цифры + 2 заглавные
латинские + 2 цифры» либо 7 символов «3 + 2 + 2»; для остальных видов — только `required` (в боевой БД 9 600 из 89 288
номеров содержат дефисы/пробелы/кириллицу — это грузовые/автобусы). e-Waybill принимал для всех видов
`[A-Za-zА-Яа-я0-9]{4,20}`.

## Как стало
Легковые — строго как в legacy; остальные — без изменений. Существующие записи не трогаются (правило действует
при создании/сохранении карточки).

## Почему
MIGRATION.md 12.2 — решение владельца 22.09 «делать все пять».

## Кто решил
Владелец (22.09). Реализация — по фактически действующему коду legacy (`withValidator`), а не по закомментированной
жёсткой регулярке для всех ТС.
