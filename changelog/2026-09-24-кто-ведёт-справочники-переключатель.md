# 2026-09-24 — Переключатель «Кто ведёт справочники»: платформа или единая платформа e-Transport

## Что изменилось
В **Настройки → Интеграции** появился блок **«Кто ведёт справочники»**: для компаний, водителей,
транспорта и сотрудников отдельно выбирается **«Вручную в платформе»** (как сейчас, по умолчанию)
или **«Единая платформа e-Transport»**.

В режиме «Единая платформа e-Transport» для этого справочника:
- кнопки «Добавить» в разделах «Компания» и «Парк» заменяются пометкой «Добавление — в единой
  платформе»; **сервер** отклоняет ручное создание (409), а не только прячет кнопку;
- у записей, пришедших из единой платформы (источник `UNIFIED`), в формах изменения закрыты все
  поля, кроме **полей модуля путевых листов**, а сервер сохраняет поля e-Transport как были, даже
  если их прислали изменёнными;
- записи, заведённые у нас раньше (перенос из старой системы, ручной ввод), остаются
  редактируемыми, пока единая платформа их не пришлёт.

Поля модуля (правятся у нас всегда): компания — доля дохода, надбавки 1–3 класса, разрешённые
виды ПЛ, выдача топлива, «Рамзи корхона», отметка на карте, планы объёма и пассажирооборота;
водитель — табельный номер, классность, закреплённое ТС; ТС — стоянка, кондиционер, одометр;
сотрудник — табельный номер.

Попутно: записи, которые единая платформа присылает через API (`POST /organizations|drivers|
vehicles|employees` учётной записью `API_INTEGRATOR`), теперь помечаются источником `UNIFIED`.
Раньше так помечались только записи из поиска по ИНН (`/sync/*`), а присланные push-каналом
оставались `MANUAL` — переключатель не смог бы их защитить.

## Как было ДО
Добавление и полная правка компаний, водителей, ТС и сотрудников были доступны всегда.
Перейти на ведение справочников в e-Transport можно было бы только выпуском новой версии.

## Как стало
В день подключения к единой платформе администратор переключает режим в настройках —
без программиста и новой выкладки. По умолчанию всё как было.

## Почему
Обсуждение с владельцем 24.09.2026: e-Waybill будет модулем единой платформы транспорта, где
компании, водители и сотрудники ведутся в общей базе со своими кабинетами. Убирать кнопки
добавления сейчас нельзя — интеграция ещё не подключена, а база — снимок старой системы на
07.08.2026, и новых водителей и ТС иначе не завести. Владелец: «лучше сделать переключатель,
как ты предлагаешь».

## Кто решил
Владелец — сделать переключатель. Разработчик (Claude) — решения:
1. проверка на сервере, а не только скрытие кнопок;
2. запись из единой платформы не блокируется целиком — поля модуля путевых листов правятся у
   нас; **состав «полей модуля» — рабочее предположение до согласования перечня полей обмена с
   командой e-Transport** (вопрос к заказчику); правится в `MasterDataSourcePolicy.MODULE_FIELDS`
   и `formFields.ts` `MODULE_FIELDS`;
3. обязательность полей (Настройки → Поля …) у записей из единой платформы проверяется только
   для полей модуля — остальные пользователь изменить не может;
4. поиск по ИНН / госномеру в единой платформе и прикрепление (`/sync/*`) остаются — это и есть
   путь получения записей из e-Transport.

## Как
- master-data: `service/MasterDataSourcePolicy` — режим по форме, `guardManualWrite` (409 на
  создание; для записи из e-Transport — новый запрос, где поля e-Transport заменены текущими
  значениями сущности), `skipRequired`. Контроллеры `Organization/Driver/Vehicle/Employee` —
  проверка для ручного ввода, отметка источника `UNIFIED` для push-канала.
  `FormFieldPolicy.requireFilled(form, record, skip)`. Миграция `V79__master_data_source_settings.sql`
  (категория `datasource`, ENUM `MANUAL,UNIFIED`, по умолчанию `MANUAL`).
- web: `formFields.ts` — `MODULE_FIELDS`, хук `useDataSource()`; раздел «Компания» и «Парк» —
  скрытие добавления, закрытые поля и подсказка; `ConfigurableFields` — `readOnly`;
  `settings/integrations/DataSourceCard.tsx` — блок с подтверждением изменений; переводы ru/tj.
- Тест `MasterDataSourcePolicyTest` (5): режим MANUAL ничего не меняет; UNIFIED — создание 409;
  у записи из e-Transport поля e-Transport сохраняются, поля модуля берутся из запроса; записи,
  заведённые у нас, правятся; **каждое защищаемое поле читается из сущности и совпадает по
  типу с полем запроса** (страховка от ошибки в списках).

## Живая проверка
Локальный стенд, `master-data` и `web` пересобраны, Flyway «now at version v79».
- Недопустимое значение режима → 422.
- Водитель, созданный диспетчером, — источник `MANUAL`; присланный учётной записью интеграции
  (`API_INTEGRATOR`) — источник `UNIFIED`.
- Режим водителей «Единая платформа»: новый водитель вручную → 409 «Водители ведутся в единой
  платформе…» (и у диспетчера, и у администратора платформы); правка записи из e-Transport с
  подменёнными Ф.И.О. и паспортом → 200, Ф.И.О. и паспорт остались прежними, табельный номер
  (поле модуля) обновился 5 → 77; запись, заведённая у нас, правится полностью.
- Возврат в «Вручную» → правка снова без ограничений. Тестовые водители (990099011, 990099012)
  удалены, режим возвращён на «Вручную».
- Playwright `form-fields.spec.ts` — 6/6: в «Парке» у водителей вместо кнопки — «Добавление — в
  единой платформе», у ТС кнопка на месте; на странице интеграций блок показывает режим.
- Регрессия: `smoke-test` 35/35, `security-matrix` 27/27.
