# 2026-09-21 — Парк: фильтры активности ТС и водителей за период (legacy active/inactive/«4-роҳхат», год выпуска) (MIGRATION.md §8.5, §8.6)

## Что изменилось
- waybill-service: `GET /api/v1/reports/activity?by=VEHICLE|DRIVER&from&to&types=WB_CAR,WB_TAXI&organizationRma=` →
  `[{key, waybills}]` — число ПЛ выбранных видов по госномеру / РМА водителя за период (агрегат в БД по `created_at`,
  все статусы, как legacy COUNT). `types` не переданы — все виды. Мультиарендность как у отчётов: тенант — своя
  область, платформа — организация или все. `from > to` → 422. Новый `ActivityReportService`,
  `WaybillRepository.countByVehicle[ForOrganizations] / countByDriver[ForOrganizations]`.
- Web `/fleet/vehicles` и `/fleet/drivers`: блок «Активность за период (по ПЛ)»: период, **форма ПЛ** (3-С = легковой +
  такси, 2-Б, 1-АД = автобус + троллейбус, 1-А, 5Б-БМ, все), **отбор**: без отбора / активные (есть ПЛ) / без ПЛ /
  ровно N ПЛ (N вводится, по умолчанию 4 — «4-роҳхат(3с)», для 2-Б — 2); для ТС ещё **год выпуска от–до**
  (`period_trans`). При активном отборе фильтруется весь парк организации (не только 50 результатов поиска), в
  первой колонке — счётчик ПЛ за период. i18n ru/tj. `api.ts`: `wb.activity(...)`.
- Тест `ActivityReportServiceTest` (3): область тенанта + виды 3-С + null-ключи; платформа без организации = все
  организации и все виды (by=DRIVER); `from > to` → 422 и пустая область.
- `ReportControllerSecurityTest` — добавлен mock нового сервиса (матрица прав 25/25 без изменений).

## Как было ДО
Legacy `ParkingCrudController::addTransportFilters`: `active_trans / inactive_trans` (ТС с/без 3-С за период),
`active2b_trans / inactive2b_trans` (2-Б), `period_trans` (год выпуска от–до), `two_waybills` «4-роҳхат(3с)» (ТС ровно
с 4 ПЛ 3-С за период), `four_waybills` «2-роҳхат(2b)» (ровно 2 ПЛ 2-Б); `DriverCrudController`: `inactive_drivers`
(без 3-С за период), `active_drivers{тип}` (с ПЛ типа за период). В e-Waybill таких фильтров не было.

## Как стало
Все legacy-фильтры активности покрыты одним обобщённым механизмом (период × форма × отбор × N), плюс год выпуска.

## Почему
MIGRATION.md 8.5/8.6 — гэпы фильтров реестров (пользователь особо подчёркивал §8); «ровно N» — контроль норматива
выдачи ПЛ.

## Кто решил
Агент Claude по промпту Шага 2. Обобщение «ровно N» вместо двух жёстких фильтров (4 и 2) — решение агента (покрывает
legacy 1-в-1 при N=4/2 и шире).
