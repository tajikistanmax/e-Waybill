# 2026-09-21 — Реестры и справочники: каскад регион→город→компания и экспорт CSV (MIGRATION.md §8.2, §8.7)

## Что изменилось
- **8.2** Web `/registry/*` (реестры ТС / водителей / сотрудников по всем организациям): список «Компания» теперь
  сужается по выбранным региону и городу (полный каскад регион→город→компания; выбранная компания, выпавшая из
  каскада, сбрасывается). Каскад регион→город уже был.
- **8.7** Кнопка «CSV» (UTF-8 BOM, `;` — открывается в Excel) в:
  - `/registry/*` — текущая выборка со всеми полями карточки (для водителей — и закреплённое ТС, источник записи);
  - `/fleet/vehicles|drivers|employees` (парк организации) — текущий список (с учётом поиска и фильтров активности),
    колонки = поля формы раздела; при активном отборе — ещё «ПЛ за период»;
  - `/dictionaries/*` (маршруты, клиенты, грузы, нормы, коэффициенты, тарифы, легаси-справочники: марки,
    направления, тарифы маршрутов и др.) — все поля записей как есть (объекты → JSON).
  Реестр ПЛ уже имел «Экспорт CSV», отчёты — CSV/XLSX.

## Как было ДО
Legacy Backpack: `enableExportButtons()` (Excel/CSV/PDF/print) на списках ТС, водителей, сотрудников, направлений,
маршрутов справок, планов и всех списках ПЛ; фильтры регион/город/компания в legacy не были каскадными (паритет
намерения — см. 8.2). В e-Waybill экспорт был только у реестра ПЛ и отчётов; список компаний в `/registry` не
зависел от региона/города.

## Как стало
Экспорт есть на всех списках (CSV); каскад фильтров полный. XLSX для реестров не делался: Excel открывает наш CSV
напрямую (BOM + `;`), а серверный XLSX есть у отчётов — при необходимости добавить по образцу `ReportXlsxWriter`.

## Почему
MIGRATION.md 8.2 и 8.7 (пользователь особо подчёркивал §8 — списки/фильтры).

Агент Claude по промпту Шага 2. Решение «CSV вместо CSV+XLSX для реестров» — агента (см. выше), зафиксировано в
MIGRATION.md 8.7.
