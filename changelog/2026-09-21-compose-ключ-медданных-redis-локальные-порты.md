# 2026-09-21 — docker-compose.prod.yml: ключ шифрования медданных и Redis для сервисов; локальный override портов

## Что изменилось
1. `infra/docker-compose.prod.yml`, сервис `waybill`: проброшены `MEDDATA_ENCRYPTION_KEY` (обязательный, синтаксис
   `${VAR:?…}` — compose откажется стартовать без ключа) и `QR_SIGNING_KEY` (постоянный ключ подписи QR) из `infra/.env`.
2. `infra/docker-compose.prod.yml`, сервис `master-data`: `SPRING_DATA_REDIS_HOST=redis` / `SPRING_DATA_REDIS_PORT=6379`
   и `depends_on: redis`.
3. Новый `infra/docker-compose.local.yml` — override для ЛОКАЛЬНОГО стенда: публикует порты бэкендов
   `8081`/`8082` на хост (регрессионные скрипты и живые проверки ходят на localhost). На сервере не применяется.

## Как было ДО
- Со слиянием серверного `main` (14.09) в waybill-service появился `MedicalDataCrypto` с обязательным ключом
  (fail-fast), а в master-data — Redis-кэш с health-индикатором. Compose при этом не обновили: ключ в
  `infra/.env` лежал, но в контейнер не попадал; хост Redis не задан → `localhost:6379`.
- Следствие при ЛЮБОМ пересоздании контейнеров: `waybill` — crash-loop («epd.meddata.encryption-key не задан»,
  27 рестартов на локальном стенде 21.09); `master-data` — `/actuator/health` = 503 (Redis недоступен), хотя
  API работал (чтение падает в БД).
- Порты 8081/8082 в серверном compose не публикуются (правильно для сервера), но локальные скрипты и
  проверки рассчитаны на `localhost:8081/8082` — старые контейнеры были созданы по прежнему локальному варианту.

## Как стало
Пересоздание стека воспроизводимо: `docker compose -p epd-rt-prod -f docker-compose.prod.yml -f docker-compose.local.yml up -d --build`.
Оба сервиса поднимаются, health UP, ключ медданных берётся из `.env` (ранее зашифрованные 389 титулов читаются
тем же ключом — новый НЕ генерировался).

## Почему
Без этого невозможно задеплоить ни одну правку (Шаг 2 промпта: деплой на локальный стек + live-проверка).
**Важно для сервера 10.10.29.70:** при следующем `git pull` + `up -d --build` compose потребует
`MEDDATA_ENCRYPTION_KEY` в `infra/.env` сервера — если там его нет, стек не стартует (осознанно: без ключа
сервис всё равно не поднимется, а падение compose нагляднее crash-loop'а). Проверить `.env` на сервере
до деплоя; если титулы Т2/Т6 на сервере уже шифровались — использовать ТОТ ЖЕ ключ.
