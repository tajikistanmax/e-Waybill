# 2026-09-23 — Образ MinIO берётся с quay.io, версия зафиксирована

## Что изменилось
В `infra/docker-compose.prod.yml` и `infra/docker-compose.yml` образ хранилища файлов MinIO
заменён с `minio/minio:latest` (Docker Hub) на `quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z`.

## Как было ДО
Compose ссылался на `minio/minio:latest` с Docker Hub. Пока образ лежал в локальном кэше Docker,
всё работало. После полной очистки Docker (23.09 диск C был переполнен, файл данных Docker
занимал 96 ГБ и был удалён) сборка стенда остановилась с ошибкой
`pull access denied for minio/minio, repository does not exist` — ни одна служба не поднялась.

## Как стало
Образ скачивается с официального реестра MinIO на quay.io, версия закреплена по тегу релиза.
Стенд с нуля поднимается одной командой `docker compose ... up -d --build`.

## Почему
MinIO прекратил публикацию образов на Docker Hub. Та же ошибка возникла бы на боевом стенде
10.10.29.70 при любой пересборке без локального кэша (новый сервер, очистка Docker).
Фиксированная версия вместо `latest` — чтобы пересборка не приносила неожиданных обновлений.

## Кто решил
Владелец поставил задачу 23.09.2026 «поднять нашу платформу и старую на Docker, чтобы работать
дальше». Выбор реестра и версии — разработчик (Claude): quay.io — официальный реестр MinIO,
версия — та, что сейчас работает на локальном стенде.

## Как
Замена строки `image:` в двух compose-файлах. Том данных MinIO не менялся.

## Как проверено
`docker pull quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z` — успешно; контейнер
`epd-prod-minio` пересоздан на новом образе (`up -d --no-deps minio`), стартовал, API отвечает.
