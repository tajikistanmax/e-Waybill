# 2026-09-21 — Тариф маршрута: «Коэффитсиенти иловагӣ» (`tariffs.adv_coe`) в справочнике (MIGRATION.md §2.26)

## Что изменилось
- master-data, миграция `V68__route_tariff_adv_coe.sql`: `route_tariff.adv_coe NUMERIC(10,4)`.
- `RouteTariff.advCoe` (nullable); `POST /api/v1/legacy-ref/route-tariffs` принимает `advCoe`, `GET` отдаёт.
- Web `/dictionaries/route-tariffs`: поле «Доп. коэффициент» в форме и колонка в таблице. i18n ru/tj.

## Как было ДО
Legacy `TariffCrudController`: колонка/поле `adv_coe` («Коэффитсиенти иловагӣ»). В e-Waybill `RouteTariff` содержал
только `pricePer1Mkm`/`priceOneTime` (+ number/typeAuto/fuelId).

## Как стало
Справочник тарифов маршрута равен legacy по полям. `advCoe` — справочное значение: в legacy оно нигде, кроме CRUD,
не используется (grep по `app/`), поэтому в `TariffMath` не подключается (паритет с legacy; см. 5.5).

## Почему
MIGRATION.md 2.26 — гэп полей справочника (Шаг 1).

## Кто решил
Агент Claude по промпту Шага 2 (перенос поля без изменения расчётов — как в legacy).

## Как проверено
- `:master-data-service:test` **70/70 ✅**; web `tsc --noEmit` ✅; `/dictionaries/route-tariffs` на пересобранном web — 200.
- **Live (локальный стек):** V68 применилась («now at version v68»); upsert тарифа маршрута с `advCoe=1.15` → в ответе
  1.15; повторный upsert без поля → null (значение берётся из запроса как есть, как остальные поля тарифа); повтор с
  1.2 → 1.2; `GET /legacy-ref/route-tariffs?routeId=` отдаёт `advCoe`.
- **Инцидент при выкладке (исправлен до коммита):** первая сборка с полем `Double advCoe` не стартовала —
  Hibernate schema-validation: «wrong column type … [adv_coe] … found numeric, expecting float(53)»; master-data ушёл
  в crash-loop на ~4 мин локального стенда. Поле переведено на `BigDecimal` (NUMERIC ↔ BigDecimal, как
  `Route.latitude/longitude`), пересобрано, стенд восстановлен. Урок зафиксирован в MIGRATION.md 2.26.
