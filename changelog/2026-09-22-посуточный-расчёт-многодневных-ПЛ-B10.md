# 2026-09-22 — Многодневные ПЛ 1-А / 3-С: посуточный расчёт включён (MIGRATION.md §5.4, B10)

## Что изменилось
- **waybill-service**: гейт B10 переведён из константы `MULTIDAY_PASSENGER_ENABLED=false` в настройку
  `epd.calc.multiday-passenger` (`MULTIDAY_PASSENGER_ENABLED`, по умолчанию **true**). При включении:
  - показатели перевозки многодневного 1-А/3-С считаются по дням (`MultiDayPassengerCalc`, уже покрыт тестами);
  - **новое — посуточный расход топлива**: строки топлива, привязанные к рабочим дням (`fuel_record.work_day_id`,
    поле было, но не участвовало в расчёте), считаются по дням классом `DailyFuelCalc` — перенос
    `app/Traits/MBusTrait.php::calcFuel` / `kvd/Bill3c1aTrait.php::calcFuel`: пробег дня по одометрам дня,
    норма = норматив марки × коэффициент дня (1 без маршрута/при `excluding_coef`, иначе `1 + 0.01·K` по дате дня —
    зима по календарю), баки расходуются последовательно (`SequentialFuel`), остаток при возврате = выдано +
    довыдано + остаток до выезда − расход. Таблица нормативов Душанбе — по региону организации (legacy
    `company.region_id == 1`). Свод по видам топлива (Σ норма, остаток первого/последнего дня) замещает результат
    движка в `/calculation` и, значит, в типовых и сводных отчётах. `View.dailyFuel[]` — разбивка по дням.
  - строки без привязки к дню → прежний расчёт по листу целиком (ничего не ломается для существующих ПЛ).
- **Web**: в карточке ПЛ (вкладка «Топливо») запись топлива получила выбор рабочего дня (когда дни есть),
  таблица топлива показывает день; блок «Посуточный расчёт» показывает разбивку по дням из `/calculation`. i18n ru/tj.

## Как было ДО
Legacy 1-А/3-С хранят `work_days` JSON с топливом по дням и считают расход посуточно при сохранении формы.
В e-Waybill посуточные метрики были реализованы, но выключены константой (B10 «придержано до одобрения»),
а топливо считалось только по листу целиком (однодневное приближение `fuel_calc_100`).

## Как стало
Паритет с legacy для многодневных листов; однодневные и грузовые не затронуты.

## Почему
MIGRATION.md 5.4 — решение владельца 22.09 «делать все пять».

## Кто решил
Владелец (22.09). Осознанные отличия от legacy (баги не переносятся): вид топлива без норматива у марки —
расход 0 (legacy подменял норму на 1 л/100 км); довыдача учитывается и при нулевой выдаче; надбавка ниже 0 °C
входит в выданное (как в однодневном `fuel_calc`); остаток до выезда дня, если не введён, берётся из остатка
предыдущего дня (legacy делал это префиллом `parking_fuel_give_multi_days`).
