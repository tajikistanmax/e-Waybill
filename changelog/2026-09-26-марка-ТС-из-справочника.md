# 2026-09-26 — Марка ТС выбирается из справочника марок

## Что изменилось
- `apps/web/app/BrandPicker.tsx` (новый) — выбор марки из справочника марок с поиском по названию, модели и коду.
  - Справочник (≈500 марок) грузится один раз.
  - При выборе марки пустые «Вместимость» и «Грузоподъёмность» заполняются из справочника.
- Выбор подключён в обе формы ТС: «Транспорт и водители» (`fleet/FleetView.tsx`) и «Компания» (`company/page.tsx`, через `overrides` у `ConfigurableFields`).
- `packages/shared/lib/api.ts` — `md.brands()`, тип `BrandRef`; `i18n.tsx` — подписи RU/TJ.
- `master-data-service/.../web/VehicleController.java` — при ручном вводе марка проверяется по справочнику:
  - нет в справочнике — 422 с подсказкой;
  - написание приводится к справочному.
- Тесты: `VehicleBrandDictionaryTest` (3), e2e `apps/web/e2e/fleet-brand.spec.ts`.

## Как было ДО
Марка — свободный текст. Расчёт ищет нормы расхода по имени марки, поэтому опечатка («КАМАС», «Kamaz 65115» вместо справочного) давала норму топлива 0 и пустые показатели. В legacy ТС ссылалось на марку из справочника (`parkings.brand_id`) — сверка 25.09, F4.

## Как стало
- В карточке ТС марку выбирают из списка справочника; под списком видны модель и код.
- Если у записи марка не из справочника (старые данные), под полем появляется предупреждение.
- Сервер при ручном вводе новую или изменённую марку принимает только из справочника.
- Когда проверка не срабатывает:
  - марка у записи не менялась — перенесённое ТС со старым написанием правится без выбора марки заново;
  - запись пришла через канал единой платформы (`API_INTEGRATOR`) — не проверяется.

## Почему
Сверка 25.09, F4: ошибка в марке тихо обнуляла норму топлива в расчёте, бланке и отчётах.

## Кто решил
- Задача — владелец (полная сверка, готовность к продакшену). Выбор из справочника — как в legacy.
- Ограничение: ТС хранит имя марки, а не id. У 4 названий в справочнике по две записи с разными моделями — расчёт берёт первую. Хранение id марки — отдельная доработка, если владелец сочтёт нужным.
