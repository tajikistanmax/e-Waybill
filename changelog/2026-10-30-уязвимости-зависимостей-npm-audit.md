# 2026-10-30 — Уязвимости зависимостей (npm audit), проверка Spring Boot CVE

## Что изменилось
`npm audit` запущен впервые за всё время проекта (не было ни в CI-истории прогонов
вручную, ни в changelog). Найдено и закрыто 3 уязвимости: Next.js (критическая),
sharp и source-map-js (высокие). Отдельно проверены актуальные CVE Spring Boot
3.4.13 (backend) — ни одна не применима к нашему коду.

## Как было ДО
- `next@15.5.25` в обоих фронтах (`apps/web`, `apps/public`): уязвим к
  неавторизованному RCE в Image Optimization API через SVG (GHSA-2464-fhr4-w9xw),
  отравлению кэша SSG/ISR (GHSA-4jqv-mc3x-m676, GHSA-mcj8-r9mp-w47p), DoS в Server
  Actions (GHSA-p3m5-59mp-jv5r).
- `sharp <0.35.5`: CVE-2026-96889 через зависимость librsvg.
- `source-map-js 1.0.0-1.2.1`: DoS через индексированные секции source-map.

## Как стало
- `next` обновлён до `15.5.28` (патч-версия внутри текущего `^15.3.4`, НЕ breaking)
  в `apps/web/package.json` и `apps/public/package.json`; транзитивно подтянулись
  исправленные `sharp`/`source-map-js`.
- Остался 1 known issue: PostCSS (XSS/directory traversal в обработке source-map) —
  тянется транзитивно через `next`, фикс есть только через `next@16` (мажорный
  breaking upgrade). НЕ применён автономно — PostCSS у нас работает только во время
  сборки (`next build`) над нашим собственным CSS, не над пользовательским вводом
  во время работы платформы, поэтому реальный риск эксплуатации сейчас низкий.
  Переход на Next 16 — отдельная задача с тестированием, не на этой неделе.
- Backend: проверены через веб-поиск актуальные (на 29.10.2026) CVE Spring Boot
  3.4.13 — CVE-2026-40992 (Mail TLS hostname verification), CVE-2026-40977
  (symlink), CVE-2026-40975 (`${random.value}`), CVE-2026-40973
  (`ApplicationTemp`/`session.persistent`). Проверено grep'ом по всей конфигурации:
  ни Mail-стартер, ни `${random.value}`, ни `session.persistent` у нас не
  используются — все 4 CVE неприменимы.
- **Отдельная важная находка (не фикс, для планирования):** весь Spring Boot 3.x
  вышел из открытой (community) поддержки с 31.12.2025; актуальный мажор — 4.1.2.
  Переход на Spring Boot 4 — крупная задача (Jakarta/Java-требования могут
  измениться), заведена в go-live чек-лист (п.5.6) как то, что нужно держать в
  виду, но не делать прямо сейчас.

## Почему
Прямое указание владельца «полностью проверь» (29-30.10.2026) — продолжение
систематического аудита. Уязвимости зависимостей никогда не проверялись вручную
за всё время проекта (CI это делает, но локального прогона/осознанного обзора не
было).
