# 2026-09-21 — Показатели «свободного»/почасового такси в живом расчёте (перенос 1-в-1)

## Что изменилось
`WaybillCalcAssembler.calculate` теперь считает пассажирские показатели для форм 3-С типов
обслуживания **METER (1, «свободное» такси)** и **HOURLY (3, почасовая)** спец-формулой оригинала
(`app/Services/Calc/Calc.php::taxi_type/hourly_type`) через уже протестированный `MultiDayPassengerCalc`.
Однодневный ПЛ — один рабочий день синтезируется из шапки (одометр выезд/возврат). `taxiServiceType`
дополнительно читает числовой `typeData.typeService` (мигрированные ПЛ), не только строковый `serviceKind`.

## Как было ДО
Для такси (нет маршрута) живой путь `WaybillCalcEngine.passengerMetrics` возвращал
`PassengerMetrics.empty()` → **все показатели перевозки = 0**. Формула такси/почасовой существовала
в `MultiDayPassengerCalc`, но вызывалась только из придержанной ветки B10 (`days>1`), т.е. в живом
однодневном расчёте не участвовала. Такси (3-С) — самый массовый тип, поэтому его отчётные
показатели (gardishi/miqdori/gasht) были нулевыми.

## Как стало
METER: `gashti_umumi = Σ(одометр возврат−выезд)`, `gasht_musofir = gashti_umumi·0.75`,
`miqdori = (gasht_musofir·(cap/2))/15`, `gardishi = miqdori·15`. HOURLY: `miqdori = (workMin/60)·4`,
`gardishi = miqdori·15`. Проверено вживую (MG3C352, METER, пробег 199): totalDistanceKm=199,
routeDistanceKm(75%)=149.25, workDays=1, speedometerBased=true. Тест
`MultiDayPassengerCalcTest.meterSingleDayFromHeader` фиксирует однодневный кейс; 119+1 расчётных тестов зелёные.

## Почему
Гэп 1-в-1 (MIGRATION.md §5.1): показатели дом­инирующего типа (такси) не считались. Нужно для
отчётов Мусофирбарӣ/Табел/Автомобил, где показатели перевозки — ключевые колонки.

## Кто решил
Владелец: перенести всю логику 1-в-1, работать автономно. Реализовал агент Claude. Спорное
(пересечение с придержанной B10) снято выбором безопасного варианта: изменены ТОЛЬКО показатели
такси METER/HOURLY (нет маршрута/begin_path — конкретная претензия к B10 неприменима), топливо и
многодневная ветка микроавтобуса/маршрута НЕ тронуты, `MULTIDAY_PASSENGER_ENABLED` остаётся false.

## Как (техническое решение)
Новая ветка в `calculate()` перед B10-блоком: для WB_TAXI/WB_CAR c svc∈{1,3} заменяет `passengerMetrics`
результатом `MultiDayPassengerCalc.forTaxi`. Однодневный ПЛ: `List.of(new PassengerDay(calcDate,…,exitOdo,
entryOdo,…))` из шапки.
