# 2026-09-23 — Расчёт отчёта по архивным листам: топливо без норматива, рейсы без маршрута, вместимость и доля дохода из справочников

## Что изменилось
Четыре правки в расчёте одного путевого листа (`waybill-service`, пакет `calc`). Через этот расчёт
идут пассажирские типовые отчёты, сводный отчёт Минтранса и тренд пассажирооборота:
1. `WaybillCalcEngine.passenger`: выданное топливо показывается и для вида топлива, по которому у
   марки нет норматива. Норма такого топлива = 0.
2. `WaybillCalcEngine.passengerMetrics`: если маршрут не найден, рейсы, выручка, касса и время
   работы сохраняются. Раньше лист получал нулевые показатели целиком.
3. `WaybillCalcAssembler`: если в снимке ТС нет вместимости, она берётся из справочника марок.
4. `WaybillCalcAssembler`: если снимок архивного листа (`migrated=true`) не несёт доли дохода,
   надбавок за класс или региона, они берутся из справочника организаций.

Тесты: `WaybillCalcEngineTest` (обновлён `missingBrand`, новые `fuelWithoutBrandNormStillReported`,
`noRouteKeepsLapsAndMoney`) и новый `WaybillCalcAssemblerArchiveTest` (5 тестов).

## Как было ДО
После загрузки показателей фазой 5b сводка и отчёт «Топливо» сошлись с legacy, а пассажирский
сводный — нет. Июль 2026, «Автобуси 2» (040000796): рейсов 13 239 вместо 15 290, выручка
745 809,01 вместо 912 475,01, выдано 0 л вместо 123 095, пассажирооборот 0. Причины:
- в справочнике марок нормативы `fuel_100` заполнены у 11 марок из 497. Движок выдавал строки
  топлива только по видам, для которых у марки есть норматив, поэтому выданное терялось;
- маршрут архивного листа ищется по названию; 1 195 из 9 245 автобусных листов июля его не
  находят, и у них обнулялись даже рейсы и выручка;
- снимок ТС архивного листа не несёт вместимость, отсюда пассажирооборот 0;
- снимок организации не несёт долю дохода, поэтому заработок водителя был 0 даже у «Троллейбус»,
  где в legacy доля 0,33.

## Почему
24.09 заказчик сверяет отчёты за прошлые периоды со старой системой. Все четыре правки
воспроизводят поведение legacy:
- `fuel_calc()` суммирует выданное по виду топлива без оглядки на нормативы;
- рейсы и выручка в legacy от маршрута не зависят;
- вместимость legacy берёт у марки (`$row->parking->brand->capacity`);
- долю дохода и надбавки legacy берёт у текущей компании (`$row->company->percent_income`, `cat_N`).

## Кто решил
Владелец 23.09.2026: «доведи платформу до запуска к демонстрации». Руководитель поставил задачу
закрыть находку 11 так, чтобы показатели были не нулевые и сходились с legacy. Реализовал агент
Claude. Решение спорное в одном месте: организацию для архивного листа берём из справочника, а не
из снимка. Для архива так и надо: снимок её не несёт, а legacy всегда берёт текущую компанию.
Живые листы продолжают считаться по снимку.

## Как
- Движок: после цикла по нормативам марки добавляются строки топлива для видов 1–3, которые выданы,
  но не нормируются: норма 0, остаток = до выезда + выдано + довыдача. Ветка «маршрут не задан»
  возвращает показатели с рейсами, выручкой, кассой и временем, пассажирооборот 0. Предупреждение в
  логе понижено до debug, чтобы не писать строку на каждый лист отчёта.
- Сборщик: `brandCapacity()` берёт вместимость через `MasterDataClient.findBrandByName`
  (кэшированный список марок). `organization(wb)` дополняет снимок полями `percentIncome`,
  `cat1..3`, `regionId` из `listOrganizations()` (кэш 60 с) по индексу РМА; индекс строится заново,
  только если сменился список. Справочник недоступен — расчёт идёт по снимку.
