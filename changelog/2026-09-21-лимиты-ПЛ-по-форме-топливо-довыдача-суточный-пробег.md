# 2026-09-21 — Лимиты ПЛ по форме: виды топлива, довыдача «Харҷи иловагӣ», суточный пробег (MIGRATION.md §12.4, §12.8, §12.5)

## Что изменилось
- `WaybillType` — атрибуты формы: `maxFuelTypes()` (2-Б, 5Б-БМ, спец, опасные — **1**; 1-АД/1-А/3-С/4М-БМ — 2),
  `maxAdditionalFuelLiters()` (1-АД автобус/троллейбус — **5**; остальные — без лимита), `maxDailyKm()`
  (1-А, 3-С — **650**; остальные 0 = без лимита).
- `WorkDayService.addFuel`: лимит видов топлива теперь по форме (было: «не более двух» для всех) — сообщение «Для
  формы 2-Б допускается не более 1 вид(ов) топлива»; довыдача в пути `additionalGiven` для 1-АД > 5 л → 422
  «Довыдача в пути для формы Т(1-АД) — не более 5 л».
- Суточный пробег (12.5): `WorkDayService.addWorkDay` — `одометр въезда − выезда ≤ 650` для 1-А/3-С;
  `WaybillService.returnTrip` — то же для ПЛ без рабочих дней (пробег по шапке = один день). **По флагу**
  `epd.limits.daily-km-enabled` (`LIMITS_DAILY_KM_ENABLED`), по умолчанию **false**.
- Тест `WorkDayServiceLimitsTest` (4): 2-Б второй вид → 422, тот же вид — ок; 1-А два вида — ок, третий — 422;
  1-АД довыдача 6 → 422, 5 — ок, 2-Б 20 — ок; 1-А день 700 км — 422 при включённом флаге, 650 — ок, при
  выключенном 700 — ок.

## Как было ДО
Legacy (`app/Http/Requests/kvd/*`, `Waybill1adRequest`, `AppServiceProvider::additional_value`): `fuels … max:1`
для 2-Б/5Б-БМ и `max:2` для 1-АД/1-А/3-С; для 1-АД `fuels.*.additional between:0,5` (в админ-форме — кастомное
правило `additional_value`, только по первой топливной строке). В e-Waybill везде допускались 2 вида топлива, лимита
довыдачи не было.

**Суточный пробег:** в legacy `max_counter_value` = 650 (3-С, 1-А) — **скрытое поле формы**, которое ни один JS
(`resources/views`, `public`) не читает; в kvd-Request'ах есть тексты `…indication_counter_exit.max => 'Максимальное
значение спидометра - 650/750'`, но самих правил `max:` нет — т.е. фактически лимит НЕ проверялся. Поэтому у нас он
реализован, но по умолчанию выключен (паритет с фактическим поведением), включение — настройкой (Вопрос 20).

## Как стало
Лимиты видов топлива и довыдачи действуют как в legacy; суточный лимит готов и включается одной переменной окружения.

## Почему
MIGRATION.md 12.4, 12.8 — действующие правила legacy, отсутствовавшие в e-Waybill; 12.5 — задекларированный, но
неработающий в legacy лимит: перенесён как настраиваемый.

## Кто решил
Агент Claude по промпту Шага 2 (12.4/12.8 однозначны; 12.5 — «неясно → безопасный вариант + вопрос владельцу»:
безопасный = не блокировать возвраты, которых legacy не блокировал).

## Как проверено
- `WorkDayServiceLimitsTest` (4); `:waybill-service:test` **262 = 260 ✅ + 2 Testcontainers-окружение** (известное
  ограничение, не регрессия).
- **Live (локальный стек):** 2-Б (5555TT01, уже есть дизель): газ вторым видом → HTTP 422 «Для формы 2-Б допускается
  не более 1 вид(ов) топлива на путевой лист»; дизель повторно → 201. 1-АД (0114TJ01): довыдача 6 л → HTTP 422
  «Довыдача в пути для формы Т(1-АД) — не более 5 л»; 5 л → 201. 2-Б довыдача 20 л → 201 (лимита нет).
  Суточный лимит при значении по умолчанию (`false`) не срабатывает — проверено юнит-тестом при `true`.
