## 🔒 СТРОГИЕ ПРАВИЛА (обязательны для каждого изменения)

После **ЛЮБОГО** изменения кода/конфигурации выполнять по порядку:

### 1. Записать в журнал изменений `changelog/`
Создать новый файл `changelog/YYYY-MM-DD-<краткое-название>.md` (формат — см. `changelog/README.md`), где по-человечески описано:
- **ЧТО** изменили (суть, список файлов);
- **ПОЧЕМУ** (какая проблема / зачем — чтобы потом было понятно, что к чему);
- **КАК** (техническое решение, почему решили именно так);
- **Хэш коммита** (заполнить после коммита);
- **Как откатить** (`git revert <hash>`).

Журнал ведётся, чтобы всегда было ясно «что к чему и почему так решили» — не пропускать даже мелкие правки.

### 2. Атомарный коммит
Один осмысленный блок изменений = один коммит. Сообщение — на русском, по сути (`fix(...)`, `feat(...)`, `chore(...)`, `docs(...)`).
Не смешивать несвязанные правки в одном коммите — иначе откат затронет лишнее.

### 3. Пуш на GitHub
```
git push origin main
```
Изменения ОБЯЗАТЕЛЬНО должны попадать на GitHub-репозиторий (не оставаться только локально/на сервере).

### 4. Возможность отката (rollback)
Каждый пуш должен быть откатываемым:
- откатить один коммит (сохранив историю): `git revert <hash>` → создаёт обратный коммит → `git push origin main`;
- посмотреть историю: `git log --oneline`;
- понять, что и почему менялось: смотреть `changelog/`.

Не использовать `push --force` и `reset --hard` на `main` без явной необходимости — это ломает возможность безопасного отката.

## Где что лежит
- `apps/backend/` — Java 21 / Spring Boot микросервисы (`master-data-service` :8081, `waybill-service` :8082).
- `apps/web/` — Next.js фронтенд (порт контейнера 3000 → на стенде опубликован на :80).
- `infra/` — docker-compose (dev и prod), Keycloak realm, init БД.
- `changelog/` — журнал изменений (что/почему/как + откат).
- `spec/` — ТЗ и QA-плейбук.

## Деплой на стенд (после пуша)
```
# на сервере 10.10.29.70 (behruz):
cd ~/e-rohkhat && git pull    # либо загрузка исходников
cd infra && docker compose -f docker-compose.prod.yml up -d --build
```
Секреты стенда — в `infra/.env` (в git НЕ коммитятся; см. `.gitignore`).
