# ТЗ: новый тип путевого листа «Мотоцикл (аренда)»

**Статус:** реализовано в коде; локальные проверки пройдены, интеграционная приёмка ожидается
**Дата обновления:** 2026-10-19
**Автор:** автономная сессия (PM-режим)
**Проект:** e-Waybill (`D:\Projects\e-Waybill`)

## 1. Бизнес-потребность

В Таджикистане действуют компании, сдающие мотоциклы в аренду. Для их деятельности
нужен отдельный вид путевого листа (ПЛ) на мотоцикл: в системе сейчас нет типа ТС
«мотоцикл» и соответствующей формы ПЛ. Требуется добавить новый тип ПЛ, по модели и
поведению близкий к легковому (3-С), но со своей категорией ТС, нормой топлива,
категорией водительского удостоверения и набором полей, уместных для аренды.

## 2. Решение (кратко)

Новый тип **`WB_MOTORCYCLE`** — «Мотоцикл (аренда)» / тадж. «Мотосикл (иҷора)».
Ведёт себя как лёгкое ТС (учёт по километражу, бензин), печатается универсальным
бланком. Вводится новый вид ТС `transport_type = 7` (мотоцикл) и норма топлива для него.

| Параметр | Значение |
|---|---|
| Код enum | `WB_MOTORCYCLE` |
| Форма (legacyForm) | `3-М` |
| Код в нац.номере (numberCode) | `11` |
| Срок действия (maxValidityDays) | 15 дней |
| Видов топлива (maxFuelTypes) | 1 (бензин) |
| Довыдача в пути (maxAdditionalFuelLiters) | −1 (без лимита) |
| Лимит суточного пробега (maxDailyKm) | 650 (как у 3-С; действует только при `epd.limits.daily-km-enabled=true`) |
| Пассажирский (isPassenger) | нет |
| Грузовой (isCargo) | нет |
| Вид ТС (transport_type) | **7 = мотоцикл** |
| Категория ВУ | **A**, если указана; категория необязательна |
| Номер ВУ | Хранится отдельно в поле `licenseNumber` |
| Норма топлива | ~3.5 л/100 км (unit=KM), редактируется админом |
| Печатная форма | универсальный бланк `print/waybill` (как спецтехника) |

## 3. Бизнес-процесс (без изменений относительно 3-С)

1. Компания (арендодатель) заводит мотоцикл в справочнике ТС с `transport_type = 7`.
2. Диспетчер выбирает водителя; номер ВУ хранится отдельно. Категория ВУ необязательна
   (в том числе для прав стран без категорий); если категория указана, проверяется **A**.
3. Диспетчер создаёт ПЛ типа «Мотоцикл (аренда)» через мастер: шаг «Тип» → организация
   / ТС (мотоцикл) / водитель → параметры, в том числе график при необходимости →
   проверка/создание.
4. Жизненный цикл ПЛ (черновик → открыт → рабочие дни → закрытие), учёт пробега и
   топлива — по общей механике лёгкого ТС (км, бензин). Маршрут — необязателен.
5. Печать — универсальный бланк с общими полями и `type_data`.

## 4. Модель данных

### 4.1. Поле типа и `type_data`

Тип хранится в существующей колонке `waybill.waybill_type VARCHAR(20)` (без CHECK —
миграция таблицы `waybill` не нужна). Вариативные поля — в JSONB `waybill.type_data`.

Поля `type_data` для `WB_MOTORCYCLE` (все опциональные — тип должен работать сразу,
детализация добавляется итеративно):

| Ключ | Тип | Назначение | Валидация |
|---|---|---|---|
| `engineVolume` | number | Объём двигателя, см³ | если задан: число 1–3000 |
| `rentalContract` | string | № договора аренды | свободная строка |
| `renterName` | string | ФИО арендатора (если не совпадает с водителем) | свободная строка |
| `renterDocument` | string | Документ арендатора (паспорт) | свободная строка |
| `workRegions` | number[] | Зоны работы (1–7), как у 3-С | каждое 1–7 |

Пробег нач/кон — общие колонки `odometerExit` / `odometerEntry`. Маршрут — общая
колонка `route` (необязательна); график — общее поле `schedule`, доступное в форме.

### 4.2. Вид ТС `transport_type = 7`

Новый код в справочнике типов ТС: `7 = мотоцикл`. Диапазон валидации в master-data
расширяется `1..6` → `1..7`. Норма топлива `fuel_norm` и (при необходимости) тариф
`tariff` заводятся для `transport_type = 7`.

## 5. Объём работ

### 5.1. Backend — `waybill-service`

1. `domain/WaybillType.java` — добавить константу
   `WB_MOTORCYCLE("3-М", "11", 7, 1, -1, 650)`. Методы `legalMaxValidityDays`,
   `maxTripKm`, `isPassenger` не трогаем (мото уходит в `default`/`false`).
2. `service/WaybillService.java`:
   - `allowedTransportTypes(...)` — **обязательно** `case WB_MOTORCYCLE -> Set.of(7);`
     (switch исчерпывающий, без `default` — иначе не скомпилируется).
   - `requiredLicenseCategories(Integer transportType)` — `case 7 -> Set.of("A");`.
   - `validateTypeData(...)` — новая ветка `case WB_MOTORCYCLE` (валидация
     `engineVolume` и `workRegions`, остальное — мягко; маршрут необязателен).
   - `PUBLIC_SERVICE_TYPES` — мото **не** добавляем (доступен всем видам организаций).
   - `isCargo(...)` — без изменений (мото не грузовой).
3. `service/Stat1AutoService.java` — `category(...)`: добавить `WB_MOTORCYCLE` в
   `case WB_CAR, WB_TAXI -> Cat.TAXI;` (**обязательно** — switch без `default`).
4. `service/WaybillNumberGenerator.java` — изменений не требует (берёт `numberCode()`
   автоматически; код «11» новый, коллизий нет).
5. Печать — `templateFor(...)` имеет `default -> "print/waybill"`; мото печатается
   универсальным бланком. Явный `case` и отдельный шаблон — опционально (не в этой итерации).

## 7. Вне объёма этой итерации

- Отдельный печатный бланк мотоцикла (пока — универсальный).
- Отдельная норма/тариф по маркам мотоциклов (пока — одна базовая норма).
- Включение мото в специализированные гос. отчёты (Stat-1 учитывается как лёгкое ТС;
  региональный норматив `normSpec` — мото не нормируется, уходит в `default`).
- Арендный блок как отдельная сущность (договор/залог/тариф как отдельная таблица) —
  при необходимости добавим позже.
