#### Сценарий № 2. Длительный рейс (более 1 суток)

**Описание:** ТС выезжает в рейс на несколько дней (например, Москва → Санкт-Петербург → Москва, 3 дня). Водитель не возвращается в гараж ежедневно.

**Особенности:**
- В Т1 указывается срок действия ЭПЛ до 5 дней (максимально разрешённый).
- Т2, Т3, Т4 заполняются перед выездом.
- Водитель находится в рейсе несколько дней, QR-код остаётся активным на весь срок.
- Т5 и Т6 заполняются после возвращения.

| Шаг | Отличие от стандартного сценария |
| :--- | :--- |
| 1 | В Т1 устанавливается срок действия = 3 дня (не более 5 дней) |
| 2 | В Т1 устанавливается признак послерейсового осмотра = «Да» (обязательно для длительных рейсов) |
| 3 | Водитель выполняет рейс в течение 3 дней, QR-код остаётся активным и обновляется |
| 4 | После возвращения заполняется Т5 (одометр въезд) |
| 5 | После Т5 заполняется Т6 (послерейсовый медосмотр), так как признак установлен |
| 6 | Т6 подписывается УКЭП |
| 7 | ЭПЛ закрывается и передаётся в ГИС ЭПД |

**Бизнес-правила:**
- Максимальный срок действия ЭПЛ — 5 дней (согласно Приказу Минтранса № 390).
- При сроке более 1 суток послерейсовый медосмотр обязателен (автоматическая установка признака при выборе срока > 1 дня).

**Требования к интеграции:**
- АДМК должен поддерживать API для передачи данных.

- Формат данных: JSON или XML.

#### Сценарий № 7. Аннулирование ЭПЛ

#### Сценарий № 10. Восстановление ЭПЛ после сбоя

**Описание:** Произошёл сбой в системе (отказ БД, сети, сервера). Требуется восстановить незакрытые ЭПЛ.

| Шаг | Действие | Ответственный |
| :--- | :--- | :--- |
| 1 | Система регистрирует сбой и запускает процедуру восстановления | Система |
| 2 | Данные ЭПЛ сохраняются в резервной копии (ежедневное полное резервирование) | Система |
| 3 | После восстановления система проверяет статусы незакрытых ЭПЛ | Система |
| 4 | Автоматически восстанавливаются все незакрытые ЭПЛ с их данными (титулы, подписи) | Система |
| 5 | Уведомление администратору о завершении восстановления | Система |
| 6 | Диспетчер проверяет восстановленные ЭПЛ и продолжает работу | Диспетчер |

**Требования:**
- RPO (Recovery Point Objective) ≤ 15 минут.
- RTO (Recovery Time Objective) ≤ 2 часа.
- Автоматическое переключение на резервный ЦОД.

#### Сценарий № 11. Перевозка опасных грузов

**Описание:** ТС перевозит опасные грузы (классы 1-9 по ADR). Требуется дополнительный контроль и обязательный послерейсовый осмотр.

**Особенности:**
- В Т1 автоматически устанавливается признак послерейсового осмотра = «Да».
- В Т1 добавляется поле «Класс опасности груза» (1-9) и «Код ООН».
- Требуется специальная подготовка водителя (отражается в Т1).
- Техосмотр включает дополнительные пункты по проверке систем безопасности (сигнализация, заземление).

**Бизнес-правила:**
- Для опасных грузов послерейсовый медосмотр обязателен (законодательное требование).
- Срок действия ЭПЛ для опасных грузов ограничен 3 днями.

#### Сценарий № 12. Перевозка скоропортящихся грузов

**Описание:** ТС перевозит скоропортящиеся продукты (температурный режим).

**Особенности:**
- В Т1 добавляется поле «Температурный режим» (например, -18°C, +2°C…+6°C).
- В Т1 добавляется поле «Срок доставки» (жёсткий дедлайн).
- Требуется контроль температурного режима в пути (интеграция с датчиками).
- Послерейсовый осмотр обязателен, если перевозилась пищевая продукция.

**Бизнес-правила:**
- Если температура нарушена, ЭПЛ автоматически получает статус «Нарушение режима».
- Инспекторы могут проверять данные о температурном режиме при проверке.

#### Сценарий № 13. Международные перевозки

**Описание:** ТС выполняет международную перевозку (выезд за пределы РФ).

**Особенности:**
- В Т1 выбирается вид сообщения = «Международное».
- Добавляются поля: «Страна назначения», «Транзитные страны», «Таможенный пост выезда».
- Требуются дополнительные документы (CMR, TIR), которые указываются в Т1.
- Срок действия ЭПЛ до 5 дней (максимум).
- Послерейсовый осмотр обязателен (влияет на безопасность международных рейсов).

**Бизнес-правила:**
- Для международных рейсов обязателен послерейсовый медосмотр.
- ЭПЛ передаётся в ГИС ЭПД как обычно, но с пометкой «Международный».

#### Сценарий № 14. Такси (легковые перевозки)

**Описание:** Легковое такси выполняет перевозку пассажиров.

**Особенности:**
- В Т1 выбирается вид перевозки = «Коммерческая», вид сообщения = «Городское».
- В Т1 добавляется поле «Разрешение на такси» (номер лицензии).
- Водитель имеет право принимать заказы по городу.
- Маршрут может быть нефиксированным (до 10 промежуточных точек).
- Послерейсовый осмотр не обязателен (по умолчанию «Нет»).

**Бизнес-правила:**
- Для такси обязателен предрейсовый медосмотр (Т2).
- Механик может проводить техосмотр упрощённо (через мобильное приложение).
- ЭПЛ может быть создан на несколько поездок в рамках одного рейса.
