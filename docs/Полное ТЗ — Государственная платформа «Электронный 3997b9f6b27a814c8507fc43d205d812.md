# 1. Общие положения

## 1.1. Наименование системы

Полное наименование: **Государственная информационная система «Электронный путевой лист»**.

Краткое наименование: **ГИС «ЭПЛ»**.

Система предназначена для цифровизации полного жизненного цикла путевого листа: от подачи заявки и проверки данных до выпуска, подписания, контроля, закрытия, архивирования и аналитической обработки.

## 1.2. Назначение системы

ГИС «ЭПЛ» создаётся как централизованная государственная платформа для оформления и контроля электронных путевых листов всех категорий транспортных средств.

Система должна обеспечить:

- отказ от бумажного путевого листа;
- единый государственный реестр электронных путевых листов;
- прозрачный контроль перевозок;
- автоматическую проверку водителей, транспортных средств, организаций и разрешительных документов;
- интеграцию с государственными информационными системами;
- юридическую значимость электронного документа;
- контроль предрейсового медицинского и технического допуска;
- контроль оплаты, лимитов и предварительно купленных пакетов путевых листов;
- предоставление данных контролирующим органам через QR-код, API и личный кабинет.

## 1.3. Основание разработки

Основанием разработки являются:

- цифровизация транспортной отрасли Республики Таджикистан;
- необходимость перехода на электронный документооборот;
- необходимость повышения прозрачности перевозочной деятельности;
- необходимость автоматизации государственного контроля;
- необходимость интеграции с налоговыми, транспортными, разрешительными, медицинскими, техническими и контрольными системами;
- необходимость исключения подделки, дублирования и несанкционированного использования путевых листов.

# 2. Цели и задачи системы

## 2.1. Основная цель

Основной целью создания ГИС «ЭПЛ» является создание единой государственной цифровой платформы для оформления, учёта, контроля и анализа электронных путевых листов в Республике Таджикистан.

## 2.2. Задачи системы

Система должна решать следующие задачи:

1. Регистрация перевозчиков, организаций, ИП, физических лиц и водителей.
2. Ведение единой базы транспортных средств.
3. Ведение единой базы водителей.
4. Ведение единого реестра электронных путевых листов.
5. Автоматическая проверка транспортного средства перед выпуском.
6. Автоматическая проверка водителя перед выпуском.
7. Предрейсовый медицинский допуск.
8. Предрейсовый технический допуск.
9. Формирование электронного путевого листа.
10. Электронное подписание документа.
11. Присвоение уникального номера.
12. Формирование QR-кода.
13. Контроль действия путевого листа.
14. Закрытие путевого листа.
15. Архивное хранение.
16. Формирование отчётности.
17. Интеграция с государственными системами.
18. Интеграция с GPS/ГЛОНАСС/BAIDU.
19. Интеграция с e-CMR и электронной ТТН.
20. Интеграция с платёжными системами.

# 5. Жизненный цикл электронного путевого листа

## 5.1. Основные статусы

| Код | Статус | Описание |
| --- | --- | --- |
| DRAFT | Черновик | Документ создан, но не отправлен |
| SUBMITTED | Подан | Заявка отправлена на оформление |
| VEHICLE_CHECK | Проверка ТС | Проверяются сведения о транспортном средстве |
| DRIVER_CHECK | Проверка водителя | Проверяются сведения о водителе |
| MEDICAL_PENDING | Ожидает медосмотра | Требуется медицинский допуск |
| MEDICAL_APPROVED | Медосмотр пройден | Водитель допущен |
| MEDICAL_REJECTED | Медосмотр не пройден | Водитель не допущен |
| TECH_PENDING | Ожидает техосмотра | Требуется технический допуск |
| TECH_APPROVED | Технически допущен | ТС допущено |
| TECH_REJECTED | Технически не допущен | ТС не допускается |
| PAYMENT_PENDING | Ожидает оплаты | Нет оплаченного лимита или счёта |
| READY_TO_ISSUE | Готов к выпуску | Все проверки пройдены |
| ISSUED | Выпущен | Путевой лист выдан |
| ACTIVE | Активен | Рейс начат |
| SUSPENDED | Приостановлен | Временно заблокирован |
| CLOSED | Закрыт | Рейс завершён |
| CANCELLED | Аннулирован | Документ отменён |
| EXPIRED | Истёк | Срок действия завершён |
| ARCHIVED | Архивирован | Документ перенесён в архив |

## 5.2. Основной процесс оформления

1. Организация входит в личный кабинет.
2. Администратор или диспетчер выбирает вид путевого листа.
3. Выбирается организация, филиал и подразделение.
4. Выбирается транспортное средство.
5. Выбирается водитель.
6. Указывается маршрут, дата, время, цель поездки, вид перевозки.
7. Система автоматически проверяет ТС.
8. Система автоматически проверяет водителя.
9. Система проверяет наличие действующих лицензий и разрешений.
10. Система проверяет оплаченный баланс или пакет путевых листов.
11. Медицинский работник проводит предрейсовый осмотр.
12. Механик проводит технический осмотр.
13. Уполномоченное лицо подтверждает выпуск.
14. Система формирует электронный путевой лист.
15. Система присваивает номер.
16. Система формирует QR-код.
17. Документ подписывается электронной подписью.
18. Водитель получает документ в личном кабинете.
19. При проверке инспектор сканирует QR-код.
20. После завершения рейса путевой лист закрывается и архивируется.

# 6. Бизнес-правила

## 6.1. Общие правила

BR-001. Система не должна позволять выпуск путевого листа без зарегистрированной организации.

BR-002. Система не должна позволять выпуск путевого листа без зарегистрированного транспортного средства.

BR-003. Система не должна позволять выпуск путевого листа без зарегистрированного водителя.

BR-004. Система не должна позволять выпуск путевого листа при недействительном водительском удостоверении.

BR-005. Система не должна позволять выпуск путевого листа при отсутствии технического допуска.

BR-006. Система не должна позволять выпуск путевого листа при отсутствии медицинского допуска.

BR-007. Система не должна позволять выпуск путевого листа при отсутствии оплаты или доступного лимита, если для выбранного типа путевого листа включена платная выдача.

BR-008. Каждый путевой лист должен иметь уникальный номер.

BR-009. Каждый путевой лист должен иметь QR-код.

BR-010. Каждый путевой лист должен иметь неизменяемую историю действий.

## 6.2. Правила оплаты

Система должна поддерживать модель предварительной оплаты:

- организация подаёт заявку на покупку количества электронных путевых листов;
- система формирует счёт;
- организация оплачивает счёт;
- после подтверждения оплаты организации начисляется лимит;
- при выпуске каждого путевого листа лимит уменьшается на 1 единицу;
- при аннулировании до момента выпуска лимит возвращается;
- после выпуска возврат лимита возможен только по регламенту, утверждённому оператором.

## 6.3. Правила аннулирования

Аннулирование возможно только до начала рейса, если:

- документ создан ошибочно;
- выбран неверный водитель;
- выбрано неверное транспортное средство;
- рейс отменён;
- обнаружены недостоверные данные.

После начала рейса документ не может быть удалён. Возможны только статусы: приостановлен, закрыт, отменён по решению уполномоченного органа.
